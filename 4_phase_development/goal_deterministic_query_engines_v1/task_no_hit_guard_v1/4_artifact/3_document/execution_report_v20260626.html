T-031 no_hit_guard_v1 执行报告

生成时间: 2026-06-26 | 任务链: T-013 CAP-05 fail → T-031 | 产出版本: pxfquery-T-031

1. 任务意图

PxFquery 项目的 ForwardQuery 在收到无意义扰动名（如 egr、egfr_random）时，会通过 token-overlap 回退机制将其误匹配到真实基因（EGR1、EGFR），产生假阳性正向查询结果。T-013 能力合同 CAP-05 将此类行为标记为失败，要求提供明确的 NOT_FOUND 安全响应。本任务的目标是创建 pxfquery-T-031 无命中安全守卫，在不破坏已有正向查询路径的前提下，为所有扰动匹配设置可调质量门槛，使无意义输入返回 found=False。

此守卫并非修复 ForwardQuery 本身（A-003 为只读上游资产），而是在本地产生一个基于继承的包装类，供当前及后续任务使用。守卫的验证同时覆盖了负向（无命中）和正向（阳性对照）两条路径，确保假阳性被阻断的同时真实查询不受影响。

2. 输入资产与依据

本任务依赖六个来源资产。A-003（T-024 pxfquery 工作区包）提供了目标类 ForwardQuery 及其模糊匹配逻辑，定位在 pxfquery/utils.py:10-48 的 fuzzy_match 函数。A-002（T-029 引擎脚本）提供了已验证的 EGFR/A549 正向查询基线。A-005（T-021 标准资源包 xpr_func_ad.h5ad）是测试的数据来源，经由 A-004（T-026 矩阵加载器）打开。A-006 和 A-007（T-013 能力合同与失败清单）确认 CAP-05 的具体要求：无意义扰动必须返回安全 NOT_FOUND，而非近-token 误配。

3. 实际执行过程

执行始于对 fuzzy_match 函数的源码分析，确认三个匹配层级中 token-overlap 回退缺少阈值控制（仅依赖 overlap > 0），导致任何单 token 重叠即被接受。基于此发现，设计了两个可调参数：min_query_length_for_substring=4 阻止短随机串（如 3 字符的 egr、bra），min_overlap_for_token_fallback=2 阻止单共享 token 的名字（如 egfr_random 只共享 egfr）。

守卫实现为 NoHitGuardForwardQuery(ForwardQuery) 子类，覆盖 query() 方法，写入 4_artifact/2_persist/pxfquery_T031_forward_no_hit_guard.py。之后执行了两个验证脚本：test_no_hit_guard.py（11 个无意义名，预期全部 found=False）和 test_positive_control.py（EGFR/A549 和 TP53/MCF7，预期 found=True 含激活和抑制项），证据分别写入 4_artifact/5_table/ 下的两个 JSON 文件。假阳性复现步骤使用未加守卫的 T-024 ForwardQuery 测试 9 个名，确认 7 个产生假阳性，复现证据写入 pxfquery_T031_false_positive_reproduced.json。

4. 关键判断与证据

执行过程中一项关键决策是使用继承而非修补策略。T-024 工作区为只读上游资产，直接修改将破坏任务 DAG 的版本隔离。因此守卫以 pxfquery-T-031 本地版本独立存在，下游任务通过 from pxfquery_T031_forward_no_hit_guard import NoHitGuardForwardQuery 替换原 ForwardQuery 即可启用。

三个证据文件支撑了本任务的主张：假阳性复现证据（7/9 无意义名触发假阳性，存在 CAP-05 失败）、负向无命中证据（11/11 被守卫正确阻断）、正向控制证据（2/2 真实查询返回正常结果，含完整激活/抑制列表）。这组证据链说明守卫在消除误报的同时未破坏核心查询路径。

6. 边界与未完成事项

本守卫仅覆盖 CAP-05 定义的扰动名模糊匹配假阳性场景。它不解决以下问题：resolver 层的语义解析错误、LLM 摘要的幻觉风险、function_index 缺失导致的无结果（那是 T-028 的目标）、以及细胞系匹配的类似模糊问题。守卫的参数（min_query_length_for_substring=4、min_overlap_for_token_fallback=2）基于当前 A-005 矩阵的扰动名分布设定，若后续引入大量短名扰动（如 2 字符基因符号），可能需要下调或动态化这些阈值。无上游资产被修改，T-024、T-026、T-029、T-021 均保持原状。
