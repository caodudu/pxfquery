# 03 功能维度路由

日期：2026-06-28

## 这个维度解决什么

用户说的功能通常不是矩阵列名。用户会说 apoptosis、immune activation、cell cycle arrest、MYC program、EMT、stemness、DNA damage response。真实 H5AD 里只有有限功能读出列。

功能路由的任务是把用户功能表达映射到真实存在的功能列，并保留方向：

```text
activate / suppress / increase / decrease / reverse
```

不能因为用户说了一个功能，就临时造一个不存在的 var_name。

这部分有 T007 源码依据：

T007 源码提供的功能资料包括：

- function aliases 到真实功能列的映射。
- `for_llm()` 给 LLM 的受控功能列表。
- 功能列来源包括 Hallmark 和 3CA MPS。
- reverse query 中从 activate/suppress 构建 target vector。

## 路由原理

功能路由应先做 alias exact match。如果用户表达可以直接映射到真实 var_name，就标为 exact function。

如果不能直接映射，LLM 可以在受控功能列表里选择候选。这里 LLM 不能自由回答功能名，必须从 `FunctionIndex.for_llm()` 暴露的列表中选，并且返回后还要再次由 function index 校验。

功能路由必须保留方向。forward query 里，功能方向影响结果解释；reverse query 里，方向直接决定 target vector 的正负号。

## T007 没有完整给出的部分

T007 提供了 function index 和 reverse target vector 的基本逻辑，但没有把功能路由单独输出成 scanpy 风格的 route artifact。

T007 也没有明确给出每个功能候选的解释证据，例如 alias 命中、LLM controlled-list 命中、人工同义词表命中之间如何编码。这是 T138 应补的 schema。

T007 没有说明如果用户问的功能没有任何真实功能列支持时该怎么呈现。T138 应该返回 unresolved function，而不是用相近词硬凑。

## L2 输出应该长什么样

功能路由输出至少要能表达：

- 用户原始功能表达。
- 规范化 function var_name。
- 方向：activate、suppress、query-only 或 unspecified。
- 命中来源：alias exact、controlled LLM selection、unresolved。
- function index 校验状态。
- 对 reverse query 是否可组成 target vector。
