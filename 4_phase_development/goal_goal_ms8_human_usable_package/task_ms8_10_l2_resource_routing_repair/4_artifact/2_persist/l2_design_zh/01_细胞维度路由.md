# 01 细胞维度路由

日期：2026-06-28

## 这个维度解决什么

用户经常不会给出矩阵里精确存在的 cell line。用户可能说“肺癌”“NSCLC”“EGFR mutant lung cancer”“breast cancer basal-like”，也可能给一个别名或上下文。真实矩阵只支持有限细胞系，所以 L2 必须把用户细胞上下文路由到实际可用细胞，或者给出受控代理。

细胞路由的目标不是“猜一个看起来像的细胞”，而是生成可审计的候选：

```text
exact cell -> same subtype proxy -> same disease proxy -> same lineage proxy -> unresolved
```

## T007 源码里直接有的资料来源

这部分有 T007 源码依据：

- `Migrated PxFquery package code/index/cellline_index.py`
- `Migrated index builder and resolver scripts/M-0370_build_cellline_index.py`
- `Migrated index builder and resolver scripts/M-0372_build_cellline_tree.py`
- `Migrated PxFquery package code/query/resolver.py`

T007 源码提供的细胞资料包括：

- `cellline_index.json`：可用细胞集合，用来确认 exact cell 是否存在。
- `cellline_neighbors.json`：按 `lineage -> disease -> subtype -> cells` 组织的层级邻居。
- `cellline_tree.json`：构建出来的树、cell index 和 meta。
- `CellLineIndex.traverse(...)`：从 lineage/disease/subtype 这类上下文往下找细胞候选。
- `CellLineIndex.proxy_cells_for(...)`：按同 subtype、同 disease、同 lineage 给代理细胞。

## 路由原理

细胞路由应该先做精确验证。用户输入如果已经是矩阵支持的 cell line，就标为 exact cell。

如果不是精确 cell，L2 需要根据 L1 提供的结构化上下文，例如 lineage、disease、subtype，去细胞树里找候选。这里不是自由文本相似度，而是受控树路径。

如果有 exact cell，但组合数据里没有这个细胞和目标扰动的 pair，L2 仍然需要展开代理细胞。代理顺序应该保留生物学距离：

```text
same_subtype 优先于 same_disease，same_disease 优先于 same_lineage
```

这和 T007 的 `proxy_cells_for(...)` 思路一致。

## T007 没有完整给出的部分

T007 源码没有把细胞路由作为独立 scanpy 风格接口暴露出来。它是在 resolver 内部一边解析、一边查索引、一边执行 query。

T007 也没有给出严格的 route candidate schema，例如每个候选的 `route_level`、`source_index`、`provider_evidence`、`availability_status` 应该如何序列化。这是 T138 需要补的。

T007 还没有明确规定 LLM 在细胞维度可以做什么。T138 应该限制为：LLM 只能辅助把自然语言上下文转成候选 lineage/disease/subtype/cell 名称，最终是否可用必须由细胞索引和 pair availability 确认。

## L2 输出应该长什么样

细胞路由输出至少要能表达：

- 用户原始细胞表达。
- 规范化后的细胞上下文。
- exact cell 是否命中。
- proxy cell 候选和代理原因。
- 每个候选来自哪个索引文件或树路径。
- 该候选在后续组合路由中是否有 pair availability。

如果这些都没有，就不应该进入 L3。
