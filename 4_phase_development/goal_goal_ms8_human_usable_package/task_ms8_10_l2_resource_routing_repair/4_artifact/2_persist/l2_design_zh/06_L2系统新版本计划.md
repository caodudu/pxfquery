# 06 L2 系统新版本计划

日期：2026-06-28

本文是基于本轮讨论整理出的 L2 新版本计划。它不是完成声明，而是后续实现和验收的设计基线。

## 一句话目标

L2 是资源感知的证据路由层。它接收 L1 的结构化意图，读取真实索引和资源包，输出一个可审计的 `RoutePlan`。它不重新解释用户全文，不计算矩阵分数，不生成总结，也不为了跑通而编造 fallback。

用户侧只需要一个 scanpy 风格入口：

```python
pxf.pp.route(qdata)
```

内部的细胞、药物、基因、功能、组合可用性都是 `pp.route` 的子步骤，不需要暴露成用户必须调用的多个 API。但这些子步骤必须写进 route artifact，方便终端检查。

## L2 与其他层的边界

L1：

```text
自然语言 -> QueryIntent
```

L1 可以说用户问的是 forward/reverse、细胞上下文是什么、扰动表达是什么、功能目标是什么。L1 不应该决定具体用哪个 cell line、BRD ID、gene proxy 或 function var_name。

L2：

```text
QueryIntent + resource indexes -> RoutePlan
```

L2 决定 exact/proxy/unresolved route，记录候选来源、LLM 使用、索引验证、pair availability。

L3：

```text
RoutePlan -> matrix result
```

L3 才读取 H5AD 数值，计算 effect、cosine ranking、reverse hits。L2 可以检查 metadata 或 pair availability，但不能输出矩阵分数。

## 总体算法

L2 的主流程应该是：

```text
1. 接收 L1 QueryIntent
2. 加载真实资源索引和 manifest
3. 对 cell / perturbation / function 分别产生候选
4. 对候选做索引验证
5. 对必要维度触发 LLM 小范围选择或补候选
6. 展开 exact/proxy route
7. 检查组合可用性
8. 生成 RoutePlan
9. 无合法 route 时返回 unresolved/no-hit
```

其中 LLM 只允许做两类事：

```text
小候选集 rerank/select
无本地候选时生成少量 hypothesized candidates
```

LLM 不能直接成为证据来源。LLM 输出必须回到索引验证。

## RoutePlan 应包含什么

`pp.route` 输出至少需要这些信息：

```text
query_id
input intent
resource pack identity
cell route candidates
perturbation route candidates
function route candidates
combination candidates
selected route
rejected candidates and reasons
unresolved dimensions
LLM calls and provider evidence
index files used
pair availability check evidence
handoff payload for L3
```

重要的是：RoutePlan 要能解释“为什么选这个 route”，也要能解释“为什么没选其他候选”。

## 细胞路由设计

细胞维度的难点是用户经常问疾病、组织、亚型，而不是矩阵里精确存在的 cell line。

细胞路由步骤：

```text
1. exact cell / alias lookup
2. 如果 exact 命中，记录 exact_cell
3. 如果没有 exact，把 L1 的 cell context 用 cellline tree 解析
4. 必要时 LLM 在 lineage/disease/subtype 的当前层选项中选择
5. 生成 candidate cells
6. 对 exact cell 也生成 proxy candidates，供组合不可用时使用
7. proxy 优先级：same subtype -> same disease -> same lineage
```

LLM 在细胞维度的作用是树遍历选择器，不是自由生成 cell line。它只能在当前层真实选项里选，最后候选必须来自 cell index/tree。

使用资源：

```text
cellline_index.json
cellline_neighbors.json
cellline_tree.json
cellline_meta_standard.csv / cellline_info_standard.csv
```

外部 Cellosaurus API 在原始代码中是构建期 enrichment，不是正式查询期 fallback。新版本可以以后设计 optional online enrichment，但默认 L2 不应实时依赖 Cellosaurus。

## 药物路由设计

药物维度不能把全量药物表交给 LLM。正确流程是本地召回优先，LLM 只处理小候选集。

药物路由步骤：

```text
1. 标准化输入：lowercase、去空格/标点、识别 BRD ID
2. drug_index exact alias / BRD lookup
3. exact 命中则生成 exact drug candidate
4. exact 不命中时，本地 fuzzy retrieval 召回 top 5-10
5. 把 top-k + 用户原词 + L1 上下文交给 LLM 选择
6. LLM 选择结果必须再过 drug_index 验证
7. 如果本地 top-k 为空，LLM 可猜 5 个潜在药物名
8. 猜测候选重新进入 drug_index/fuzzy retrieval
9. 仍无验证命中则 unresolved
10. exact drug 无组合证据时，用 drug_neighbors 做 Tanimoto proxy
```

本地 fuzzy retrieval 不应只靠字母重叠，应该至少组合：

```text
normalized exact
token overlap
edit distance / rapidfuzz
character n-gram
prefix/suffix
alias field
BRD ID format
```

药物 proxy 来源：

```text
drug_neighbors.json
```

这个近邻来自 PubChem SMILES、RDKit Morgan fingerprint 和 Tanimoto similarity。PubChem 在原始代码中是构建期 enrichment，不是正式查询期 route fallback。

## 基因路由设计

基因维度也不能把 78k gene index 交给 LLM。它应和药物一样，本地召回优先，LLM 只做小候选选择。

基因路由步骤：

```text
1. 标准化输入：大小写、符号清洗、常见别名形态
2. gene_index exact lookup
3. gene_index_simple uppercase lookup
4. exact 命中则记录 gene_type 和 in_matrix
5. exact 不命中时，本地 fuzzy retrieval 召回 top 5-10
6. 把 top-k + 用户原词 + L1 上下文交给 LLM 选择
7. LLM 选择结果必须再过 gene_index 验证
8. 如果本地 top-k 为空，LLM 可猜 5 个潜在 gene symbols
9. 猜测候选重新进入 gene_index/fuzzy retrieval
10. 仍无验证命中则 unresolved
11. exact gene 若 in_matrix=True，可形成 exact gene route
12. exact gene 若 in_matrix=False，可走 GenePT neighbor proxy
```

基因 proxy 来源：

```text
gene_neighbors.json
gene_neighbors_simple.json
```

这个近邻来自 GenePT embedding 的 cosine similarity。它不是 LLM 现场猜的，也不是字符串相似。

### 非编码基因亮点

完整 `gene_index.json` 支持 lncRNA、miRNA、snRNA、misc_RNA、pseudogene 等广义 gene type。这一点应作为方法和 figure 亮点保留。

亮点不是“所有非编码基因都有直接扰动实验”，而是：

```text
lncRNA / non-coding query
-> broad Gencode/GenePT recognition
-> in_matrix availability gate
-> 如果无直接扰动数据，用 GenePT neighbor 找 matrix-supported proxy genes
-> 形成带证据等级的 proxy prediction
```

这相当于把没有直接 perturbation data 的非编码基因问题，转成受控语义近邻证据迁移。输出必须标成 proxy prediction，不能标成 direct experimental evidence。

## 功能路由设计

功能维度和药物/基因不一样。功能空间不是几万候选，而是 H5AD 中固定 91 个 function var_names。

功能路由不能简单“挑 1 个”或“全部挑出”。它要按 query direction 和用户表达模糊度控制候选数量。

基础步骤：

```text
1. 读取 function_index.json
2. 先做 alias / exact var_name lookup
3. 命中则生成 exact function candidate
4. 未命中时，把 function_index.for_llm() 或等价 91 项列表交给 LLM
5. LLM 只能从这 91 个真实 var_names 中选择
6. LLM 返回后必须 function_index.validate()
7. 无验证命中则 unresolved
8. 保留 activate/suppress 方向
```

老版本机制就是这个：先查表，再让 LLM 从固定功能列表挑选。它不是功能近邻图，也不是让 LLM 自由创造功能名。

### Forward 功能候选数量

Forward 查询中，功能路由用于决定要查看哪些功能列。用户给出明确功能时，默认应少选；用户表达宽泛时，允许多个候选，但不能全选。

默认策略：

```text
明确单功能：top 1，最多保留 top 2 作为 ambiguity candidate
中等模糊功能：top 3
宽泛表型：top 5，并标记 broad_function_route
```

Forward 的 function candidates 可以一起交给 L3 读取这些列的数值，因为它们只是同一个 perturbation/cell route 下的多个读出列。

### Reverse 功能候选数量与三次解释集

Reverse 查询中，功能候选会构造 target vector，直接影响 perturbation ranking。因此 reverse 不应默认把一次 LLM 返回的所有功能候选混成一个大 target vector。

Reverse 功能路由默认执行 3 次受控 LLM mapping，用于回答“怎么保证 LLM 对模糊功能理解不是偶然”的问题。

三次 mapping 不是把全量功能交给自由生成模型，而是：

```text
同一个用户功能表达
同一个 91 项 function var_name 列表
三次受控选择
每次生成一个 interpretation set
每个 set 内最多 3 个 function terms
宽泛 profile 查询时每个 set 最多 5 个 function terms
每个 term 必须 function_index.validate()
```

三次 mapping 应使用不同解释角度，避免 temperature=0 时重复同一个答案：

```text
pass 1: direct/literal interpretation
pass 2: mechanism/program interpretation
pass 3: phenotype/outcome interpretation
```

输出单位不是单个 function，而是 interpretation set：

```text
function_interpretation_sets:
  - set_id: direct
    label: direct functional reading
    functions: [...]
    polarities: [...]
    validated: true
  - set_id: mechanism
    label: mechanistic program reading
    functions: [...]
    polarities: [...]
    validated: true
  - set_id: phenotype
    label: phenotype/outcome reading
    functions: [...]
    polarities: [...]
    validated: true
```

每个 interpretation set 应独立形成 reverse route，并分别交给 L3 ranking。L2 不默认把三个 set 合并成一个 target vector。L4 再比较三个 interpretation sets 的结果是否收敛：

```text
shared top perturbations
set-specific perturbations
unstable/no-consensus warning
```

只有当用户明确表达组合目标时，才构造 combined target vector，例如：

```text
activate apoptosis and suppress MYC
increase immune response while decrease proliferation
```

功能资源状态：

```text
legacy 原始 function_index.json 存在，但 T002 漏迁
T021 已恢复到 standard_resources
```

T138 固定采用 T021 `standard_resources/function_index.json` 作为运行时 `function_index.json`，不做多 schema 兼容，也不再引用其他 function index pack。

## 组合可用性设计

单维度命中不等于组合可执行。L2 必须检查 `(cell, perturbation, modality)` 的可用性。

组合路由也必须限制数量。局部路由可以产生多个候选，但每个维度都要有 beam limit；forward/reverse 都通过 beam-limited route composition 生成有限数量可审计 route。

默认局部上限：

```text
cell candidates <= 6
perturbation proxy candidates <= 5
forward function terms <= 5
reverse interpretation sets = 3
reverse functions per set <= 3，宽泛 profile <= 5
selected/supporting routes <= 3
```

### Forward 组合路由

Forward 组合要检查 `(cell, perturbation, modality)` pair availability。旧代码顺序应保留：

```text
exact cell + exact perturbation
exact cell + proxy perturbation
proxy cell + exact perturbation
proxy cell + proxy perturbation
```

默认采用 cell-anchor priority：优先保持用户细胞上下文，再替换扰动。因此 `exact cell + proxy perturbation` 默认优先于 `proxy cell + exact perturbation`。如果 L1 intent 明确强调 exact perturbation 更重要，可以切换到 perturbation-anchor priority。

Forward 默认 beam：

```text
proxy cells <= 6
proxy perturbations <= 5
pair availability checks <= 25
selected/supporting routes <= 3
```

搜索方式：

```text
Stage A: exact cell + exact perturbation
Stage B: exact cell + top proxy perturbations
Stage C: top proxy cells + exact perturbation
Stage D: top proxy cells + top proxy perturbations
```

Stage D 不做无限笛卡尔积，只在 `pair availability checks <= 25` 内检查最高优先级组合。

这一步检查 metadata 或 pair availability，不读取矩阵数值。

### Reverse 组合路由

Reverse 组合不是 `(cell, perturbation)` pair 检查。它主要检查：

```text
cell scope
function interpretation set / target vector
search modality
available perturbation universe
```

Reverse 的细胞候选也必须限制数量。即使功能列在每个矩阵里都有，疾病/上下文路由仍可能产生多个近邻细胞系。

默认策略：

```text
exact cell: 1
context/proxy cell candidates <= 6
search modalities: 由 intent 指定；未指定时 cp/xpr/sh 最多 3 个 universe
reverse route candidates <= cell_candidates * interpretation_sets * modality_count，但必须受上限控制
selected/supporting reverse routes <= 3 per interpretation set 或由 L4 汇总
```

如果用户问的是模糊功能目标，reverse 默认生成 3 个 function interpretation sets。每个 set 在每个 selected cell scope 下独立形成 route，不默认合并。这样可以把 LLM 对功能理解的不确定性保留下来，并交给 L4 汇总共识/分歧。

组合候选需要记录：

```text
route_id
cell candidate
perturbation candidate
function candidates 或 interpretation set
modality
availability status
evidence level
reject reason if rejected
```

## LLM 使用原则

L2 可以用 LLM，但只能在受控位置使用。

允许：

```text
细胞树当前层选择
药物 top-k 候选重排
基因 top-k 候选重排
药物/基因无候选时生成少量 hypothesized candidates
功能 91 项 controlled-list selection
reverse 功能目标默认三次 controlled-list interpretation mapping
```

禁止：

```text
把全量药物/基因表塞给 LLM
LLM 直接返回最终 route
LLM 返回未通过索引验证的药物/基因/功能
LLM 编造不存在的 function var_name
LLM 编造 pair availability
无资源证据时 forced fallback
```

所有 LLM 调用必须记录：

```text
provider
model
prompt type
input candidate set
raw output
validated output
discarded output and reason
```

## 失败状态

L2 失败不是异常地继续跑，而是正式输出状态。

常见状态：

```text
missing_intent_field
cell_unresolved
perturbation_unresolved
function_unresolved
no_pair_available
resource_missing
llm_unavailable
llm_output_invalid
no_route
```

其中 `llm_unavailable` 不能自动降级成本地 demo。可以返回“需要 LLM 的路由步骤未完成”，也可以只执行不需要 LLM 的 exact path，但不能伪造 LLM 结果。

## 实施顺序

建议实现顺序：

```text
1. 定义 RoutePlan schema
2. 接入资源 registry / manifest
3. 实现 function_index 读取和功能路由
4. 实现 gene/drug exact + fuzzy top-k retrieval
5. 实现 LLM top-k selection protocol
6. 实现 cell tree route
7. 实现 proxy expansion：drug Tanimoto / gene GenePT / cell hierarchy
8. 实现 pair availability check
9. 接入 pp.route
10. 写终端可复现测试
```

优先先把 `pp.route` 做成真实可检查的预处理产物，再接 L3。

## 验收标准

最低验收不看漂亮输出，看能不能证明不是 demo。

必须能证明：

```text
1. 未配置资源时，明确 resource_missing
2. 未配置 LLM 且需要 LLM 时，明确 llm_unavailable
3. exact drug/gene/function/cell 不触发 LLM
4. fuzzy drug/gene 只给 LLM top-k，不给全量表
5. LLM 输出必须过索引验证
6. function route 只能输出真实 91 var_names
7. reverse 模糊功能查询默认生成 3 个 validated interpretation sets
8. lncRNA 类查询能进入 gene_index，并按 in_matrix 决定 exact/proxy/unresolved
9. forward pair availability checks 有上限，no pair available 时不进入 L3
10. reverse cell candidates 有上限，不把近邻细胞无限展开
11. RoutePlan 记录候选、拒绝原因和资源来源
12. 没有硬编码 demo 输入输出
```
