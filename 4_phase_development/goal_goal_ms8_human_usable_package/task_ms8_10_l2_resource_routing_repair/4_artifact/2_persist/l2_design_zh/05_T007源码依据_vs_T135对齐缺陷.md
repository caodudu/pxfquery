# 05 T007 源码依据 vs T135 对齐缺陷

日期：2026-06-28

## 先明确：T007 不是五层架构

T007 原始源码不是干净的 L1/L2/L3/L4/L5 分层。它的价值在于里面保留了真实路由逻辑和资源索引用法，而不是架构已经正确。

T007 大体是混合流程：

```text
LLM 解析意图
资源索引映射和代理路由
forward/reverse 矩阵查询
LLM 总结
```

这些步骤在 resolver 和 query 代码里交织在一起。

## T007 中对 L2 有价值的部分

T007 对 L2 有价值的是资源感知逻辑：

- 细胞：valid cells、cell tree、same subtype/disease/lineage proxies。
- 药物：alias 到 BRD、结构近邻、Tanimoto neighbor。
- 基因：gene symbol、in_matrix、xpr/sh 可用性、GenePT neighbors。
- 功能：function aliases、受控功能列表、真实 H5AD var_name。
- 组合：exact/proxy cell 和 exact/proxy perturbation 的证据优先级。

这些都应该被保留并拆成 L2 的正式 route plan，而不是被简化成 keyword toy。

## T007 的缺陷

T007 的问题不是“没有路由思想”，而是边界不清：

- LLM parse、resource routing、matrix execution 混在一起。
- 没有独立 scanpy 风格 `pp.route` 产物。
- LLM 输出和本地 fast path/fallback 混用。
- `must_answer` 可能强行返回弱证据。
- 失败状态不够硬，容易从 no-hit 滑到 forced fallback。

所以 T138 不能照搬 T007 的结构，但必须继承 T007 真实资源路由逻辑。

## T135 做对的地方

T135 尝试把包切成五层，这是方向上对的。它也把一部分 T007 resolver/index/query 逻辑搬进了导出包，因此原材料没有完全丢失。

T135 的价值主要是：

- 提出了 L1 到 L5 的层级目录。
- 保留了 legacy resolver 里的部分资源逻辑。
- 让后续可以把 route 作为单独层拉出来。

## T135 的关键缺陷

T135 的 L2 没有真正跑通。表面上有 `l2_routing`，但 scanpy 风格的 route 接口只做很浅的 intent 字段检查，没有真正读取 cell/drug/gene/function index，也没有生成可执行的 evidence route。

实际有价值的路由仍然藏在 resolver 的 execute 路径里。也就是说：

```text
pp.route(q) 不是完整 L2
tl.execute(q) 内部才在做一部分 legacy routing
```

这违反了 T138 目标。T138 要求 L2 在执行前就能单独交付 route plan，让用户能检查每一层预处理。

## 当前修复方向

T138 不应该新造 demo router。它应该做的是：

1. 从 T007 源码恢复真实 cell/drug/gene/function routing 依据。
2. 把 T135 混在 execute 里的资源映射提前到 L2。
3. 让 `pp.route` 输出完整 route artifact。
4. 严格禁止硬编码 demo、regex toy、LLM bypass 和 forced fallback。
5. 对每个 unresolved 维度给出明确失败原因。
