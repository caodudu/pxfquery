# 00 L2 总边界：为什么需要路由

日期：2026-06-28

本文只说明 L2 的任务边界和存在原因，不声明实现已完成。

## 核心问题

PxFquery 的真实证据不是按用户自然语言存放的，而是落在几个资源坐标上：

```text
细胞上下文 x 扰动对象 x 扰动方式 x 功能读出
```

用户真正关心的问题往往不是这些精确坐标。用户会问疾病、细胞类型、药物类别、机制、通路、基因功能、表型方向，但资源里未必有完全匹配的细胞、药物、基因、扰动方式和功能列。

所以 L2 的核心不是“把字段检查一遍”，也不是“把名字查字典”。L2 要做的是在资源允许范围内，把用户意图路由到可审计的证据路径上。精确证据存在时使用精确证据；精确证据不存在时，按受控规则找代理证据；连代理证据也没有时，必须返回 unresolved/no-hit，不能编造结果。

## L1 和 L2 的边界

L1 负责理解用户语言，输出结构化意图。例如：

```text
用户问 EGFR 抑制剂在肺癌细胞中对凋亡和 MYC 相关功能的影响。
```

这仍然只是意图。它不能决定用哪个具体细胞系、哪个 BRD 药物、哪个 HALLMARK 功能列。因为这些决定需要资源索引、矩阵可用性、近邻关系和证据等级。

这些资源相关决策属于 L2。

## L2 和 L3 的边界

L2 可以判断：

```text
候选路线 1：A549 + erlotinib + HALLMARK_APOPTOSIS，证据等级 exact_cell/exact_pert/exact_function。
候选路线 2：H1975 + gefitinib + HALLMARK_APOPTOSIS，证据等级 proxy_cell/proxy_pert/exact_function。
```

但 L2 不应该计算矩阵分数，也不应该生成扰动排序结果。H5AD 里的实际 effect size、cosine ranking、功能分数读取属于 L3。

L2 可以读取或依赖资源包里的 metadata/pair availability，用来判断某个 `(cell, perturbation, modality)` 是否存在；但它不能把矩阵数值当成自己的输出。

## L2 必须覆盖的路由维度

L2 至少需要覆盖五类路由：

1. 细胞维度：把疾病、组织、亚型、细胞系名字映射到实际矩阵支持的细胞，并给出同亚型、同疾病、同 lineage 的代理候选。
2. 扰动维度：把药物、药物别名、BRD 编号、基因符号、基因扰动方式映射到资源中存在的扰动对象，并给出结构或语义近邻代理。
3. 功能维度：把用户说的表型、通路、机制映射到 H5AD 中真实存在的功能列，不能自由生成不存在的功能名。
4. 组合证据路由：单个维度能匹配不代表组合存在，必须检查 `(细胞, 扰动, 功能/读出)` 的组合是否有数据。
5. forward/reverse 方向路由：forward 是给定扰动找功能影响；reverse 是给定功能目标找扰动，二者路由对象和失败方式不同。

## 失败原则

L2 不能为了让流程跑通而降级成 demo。

禁止行为：

- 本地硬编码几个输入输出冒充路由。
- 用 keyword/regex 替代真实 LLM 查询。
- LLM 返回什么都相信，不经过资源索引校验。
- 没有真实 pair availability 时假装存在证据。
- 没有功能列时临时造一个功能名。
- 因为“临时 MVP”而返回 forced fallback 结果。

允许行为：

- 返回 unresolved，并说明卡在哪个维度。
- 返回 no-hit，并列出检查过的资源路径。
- 返回多个候选 route，并标注 exact/proxy/unresolved。
- 把 LLM 输出作为候选生成来源，但最终必须由资源索引和可用性检查确认。
