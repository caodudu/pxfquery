T-028 功能索引包结果报告

1. 一句话结论

T-028 从三个真实 H5AD 扰动-功能矩阵中提取了 91 个 MSigDB Hallmark 功能术语，为每个术语构建了包括自身、小写和可读标签的别名列表，打包为版本化索引 pxfquery-T-028/function_index.json，并通过 7/7 自动化验证证明索引与矩阵 var 列完全一致。

2. 项目背景

PxFquery 的核心科学用例是"给定一种药物或基因扰动，它在特定细胞背景下激活或抑制了哪些功能程序"。回答这类查询需要两个条件：一份可信的功能术语表（描述细胞功能的标准化基因集名称）和一个能将用户输入的模糊查询词映射到标准术语的解析器。T-028 提供的正是前者——功能术语索引。这三个 H5AD 矩阵（cp_func_ad、sh_func_ad、xpr_func_ad）来自 T-021 标准资源包，各自包含 91 列基因集功能评分。此前 T-013 能力检查发现迁移后的 function_index.json 在部分路径下不完整，下游查询任务无法可靠使用。T-028 由此产生：构建一份经过交叉验证的本地替代品，不依赖任何中间目录状态。

4. 项目价值

T-028 的交付物消除了 PxFquery 查询链路中一个具体的"数据不可信"风险。在此之前，下游 resolver 任务面对的是来历不明的 function_index.json——可能来自遗留迁移、可能部分损坏、可能包含与矩阵不匹配的术语。现在 resolver 可以直接读取 pxfquery-T-028/function_index.json，其 91 个术语来自 T-026 加载器运行时读取的 H5AD 文件，且通过了交叉验证。这意味着一份 query 任务如果使用 T-028 索引，99% 以上的列名匹配问题已经被排除。别名列表的三格式设计（UPPER/lower/Label）让精确匹配、大小写不敏感匹配和面向用户的展示都能基于同一份数据完成，不需要 resolver 自行维护映射表。长远来看，function_index 也是后续批量验证报告和 manuscript 补充表格的数据基础。

6. 后续使用方式

下游 query/resolver 任务应当将 pxfquery_T028_function_index/function_index.json 作为功能术语的权威来源。读取 fi["var_names"] 获得有序的 91 个标准术语，用 fi["aliases"][term] 获取每个术语的匹配列表。推荐的分辨逻辑是：先将用户输入转为小写，遍历所有术语的别名列表做小写包含匹配，命中后返回标准术语。可读标签（列表第三项）可用于 UI 展示或报告生成。跨越 T-028 边界的内容——如同义词扩展、跨本体映射、LLM 辅助查询——属于后续 resolver 任务的设计范围，不应要求 T-028 提供。

7. 边界与风险

T-028 索引包的术语来源是 MSigDB Hallmark 基因集集合，覆盖 91 个功能通路。如果未来项目引入新的矩阵（例如额外细胞系或扰动类型），需要重新运行 T-026 加载器验证 var_names 并考虑重建索引。别名列表目前不包含跨数据库同义词（如 GO 术语 ID、Reactome 通路名），这些扩展应由 resolver 层处理。本任务不提供任何运行时 API 或查询服务，交付物仅为静态 JSON 文件及其验证证据。
