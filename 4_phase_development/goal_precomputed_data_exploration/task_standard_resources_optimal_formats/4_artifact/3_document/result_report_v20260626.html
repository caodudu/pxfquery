PxFquery 标准内置资源 — 最优格式结果报告

T-021： standard_resources_optimal_formats | 日期： 2026-06-26

项目： PxFquery (P-012) — LINCS 扰动-功能分析工作流

一句话结论：基于 T-014 梳理的遗留预计算数据，本次任务识别、优化并验证了 19 个 PxFquery 标准内置资源，将原始 1,473 MB 的 float64 矩阵压缩为 323 MB 的 float32 资源包（压缩率 78%），所有文件均通过 Python 验证，可直接供下游开发和测试使用。

一、项目背景

PxFquery 项目的核心能力是通过 forward query（扰动→功能响应）和 reverse query（功能靶标→候选扰动）两种模式，查询药物和基因诱导的细胞功能程序。这一能力的运行时基础是一套预计算的功能矩阵和查询索引，它们来自 CMAP/LINCS 项目的公开数据。然而，遗留资产经历了多轮迁移和格式变更，存在重复版本、缺失文件、精度冗余等问题——例如三套功能矩阵各有两套字节完全相同的副本，而 function_index.json 从 T-007 阶段起就一直缺失。

此前的 T-014 任务完成了预计算数据的系统清查（66 个文件）、矩阵模式评估（11 个 H5AD）、以及六项后续任务提案。T-021 是这六项提案中优先级最高的数据基础任务：它需要从 "已梳理但尚未最优化的数据" 中，提炼出 PxFquery 包实际使用的标准资源集，并为每个资源确定最佳存储格式。这一任务的产出将直接决定后续所有开发任务（包括查询引擎、Web 界面、安装打包）所使用的数据基础。

功能矩阵 — 压缩效果

三个功能矩阵从原始 float64 格式（共 1,473 MB）转换为 float32 h5ad 后仅占 265 MB，缩水 82%。所有 273 列（91 个功能术语 × 3 种扰动类型）的秩相关系数均为 1.000000，最大绝对误差仅 0.00025（评分范围 -10 到 +10）。这意味着压缩完全没有影响查询结果的排序质量。

  • cp_func_ad.h5ad： 201,014 × 91，105 MB（原 569 MB，−82%）
  • sh_func_ad.h5ad： 189,365 × 91，96 MB（原 533 MB，−82%）
  • xpr_func_ad.h5ad： 132,464 × 91，64 MB（原 370 MB，−83%）

查询索引 — 标准补齐

10 个查询索引 JSON 文件共 56 MB，覆盖细胞系（index + neighbors + tree）、药物（index + neighbors）、基因（simple 版 + 完整版）、以及功能术语共五大域。其中 function_index.json 是本次任务从矩阵 var 中重新构建的，补齐了从 T-007 起持续存在的索引缺口。重建后的索引包含 91 个术语（50 个 HALLMARK + 41 个 3CA MPS）及其来源、标签和别名信息，结构与 pxfquery FunctionIndex 类完全匹配。

元数据 — 去重整合

五张 CSV 元数据表共 6.25 MB，覆盖 240 个细胞系、6,647 种化合物（含 SMILES/InChIKey）、39,321 条化合物详细注释、12,328 个基因注释条目。在遗留资产的两套重复版本中，选择了 Cellosaurus 和 PubChem 注释更丰富的版本。

三、项目价值

本次任务对 PxFquery 项目的推进体现在三个层面。在数据层面，标准资源包的体积缩减到原始的三分之一以下，使后续的安装包分發、测试环境搭建和 CI/CD 流程的负担显著降低。一个开发者从一个空环境搭建 PxFquery 现在只需要下载 323 MB 的数据资源，而不是原来的近 1.5 GB。在可靠性层面，所有标准资源都经过了 Python 加载验证和数据完整性检查，18 个文件全部通过；这意味着后续开发中遇到的数据相关 Bug 几乎不可能来自标准资源本身，减少了调试时的排查范围。

在任务链层面，function_index.json 的补齐消除了一个持续了两个任务（T-007、T-014）的技术债务。现在 PxFquery 包的所有 index 类（CellLineIndex、DrugIndex、GeneIndex、FunctionIndex）都能正确加载对应的 JSON 文件。此外，格式评估的记录——包括 float32 的秩相关性证据、parquet/feather 的兼容性测试、拆分方案的可行性分析——为项目后续可能需要的存储优化决策提供了可复用的实验数据。特别是 float32 无精度损失这一结论，如果写在最终论文的方法部分，也是一个有说服力的技术点。

四、交付物导读

如果只打开一个交付物，请先看 4_artifact/2_persist/pxfquery_standard_resource_guide_v20260623.md，它列出了全部 19 个标准资源的文件名、格式、大小、模式和使用方式，并逐项说明了每个格式决策的理由。如果发现数据异常需要排查，可查看 4_artifact/2_persist/process_records/ 下的过程记录文件，特别是 step5_verification_results.json 中的每项检查详情。

实际的标准资源文件位于 4_artifact/2_persist/standard_resources/。如果后续开发或测试任务需要引用这些文件，应直接使用此路径。对于安装打包任务，需要额外处理路径映射——将标准资源从 artifact 路径复制到包的 data/ 目录下——但这不属于本任务范围。

五、后续使用方式

面向 PxFquery 开发者的标准工作流是：通过 DataLoader.load_all_local() 加载三个 H5AD 矩阵，这一步需要将 standard_resources/ 下的 cp/sh/xpr_func_ad.h5ad 放置于包可访问的 data 路径。加载后，obs 中的 sig_id、cell_iname、pert_id 等字段可直接用于查询过滤，var 的 91 个功能术语可直接用于评分索引。

查询索引的使用方式更为直接：各 index 类（CellLineIndex、DrugIndex、GeneIndex、FunctionIndex）接收对应 JSON 文件的路径即完成初始化。在标准资源包中，所有 JSON 文件的格式都与这些类的构造函数完全匹配。后续的 Web API、CLI 交互、以及 Resolver 层都将在此基础上构建。元数据表主要用于查询结果的注释增强，可在 pandas 中以 DataFrame 形式按 pert_id 或 cell_iname 联接到查询结果上。

六、边界与风险

已知风险： 五个 CMAP 上游 H5AD 文件在遗留迁移时已截断损坏，无法恢复。这些文件不是 pxfquery 包运行的必要输入，但它们是某些 CMAP 原始管线的中间产物，如果未来需要完整复现 CMAP 处理流程，这五个文件需要从源头重新获取。

另一个需要注意的边界是标准资源的生命周期管理。当前 19 个文件是在 2026-06-23 锁定的版本，如果后续更新了上游预计算数据（例如 LINCS 发布新一期处理结果），标准资源需要重新执行 T-021 流程来更新。目前没有自动化的版本更新机制。此外，CSV 元数据表中的 "beta" 注释字段来源于遗留资产的直接迁移，未经独立的生物学审核——在正式发表前建议交叉验证关键细胞系和化合物的注释准确性。路径映射问题（artifact 路径 vs 包内 data 路径）需要在后续的安装打包任务中解决，当前不做处理。
