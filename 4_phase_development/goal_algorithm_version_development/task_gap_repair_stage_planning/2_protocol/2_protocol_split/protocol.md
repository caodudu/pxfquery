# Protocol: gap_repair_stage_planning

## Objective
基于 T-013 MVP走查的失败与缺口清单，结合 T-007 的开发状态理解与 T-012 的 Genes 论文模式分析，提出 PxFquery 算法缺口修复的阶段规划。本 task 只做规划，不执行修复。

## Inputs
- A-001: 当前项目协议 — 约束开发姿态、环境规则、轻量 Genes 投稿路线。
- A-002: T-013 MVP 能力契约 — 定义哪些是必需门控能力、哪些是可选/门控行为、哪些禁止声称。
- A-003: T-013 失败与缺失能力清单 — 列出 CAP-03（索引不可用）、CAP-05（未命中误报）、CAP-06（反向查询数值warning）、CAP-07（NL resolver 阻断）及下一步建议。
- A-004: T-013 能力状态矩阵 — 完整 pass/partial/fail/blocked 状态表。
- A-005: T-007 开发状态报告 — 理解 PxFquery 已有模块、设计意图、数据/索引准备程度、真实完成边界。
- A-006: T-007 开发阶段交接 — 推荐的后续开发任务和 carry-forward 指导。
- A-007: T-012 Genes 论文可交付物目录 — 理解 Genes 接受的 bioinformatics 可交付物论文的描述模式、弱但可容忍的验证模式、及交付物措辞惯例，确保修复规划产出的交付物在论文层面有说服力。
- A-008: 迁移的 PxFquery 包代码 — 理解需要修改的包结构、resolver 入口、索引加载逻辑和路径约定。
- A-009: 迁移的设计文档 — 理解 resolver 设计意图、索引命名约定、builder 脚本逻辑。
- A-010: 迁移的查询索引目录 — 检查当前索引文件命名、结构、缺失项（function_index.json）。
- A-011: 迁移的索引构建脚本 — 理解 function_index 和其他索引是如何生成的，为修复提供技术参考。
- A-012: T-007 缺口的开发与风险清单 — 理解宏观层面已知的开发风险和缺口。

## Steps
1. 读取 T-013 失败与缺失清单、能力状态矩阵、能力契约，逐条整理每个缺口（fail/partial/blocked）的技术根因、当前证据、T-013 禁止的修复方式、和 T-013 建议的修复方向。
2. 读取 T-007 开发状态报告和交接文件，补充每个缺口在代码/索引/数据层面的背景，确认哪些修复属于“已有代码但配置/索引不对”，哪些属于“代码逻辑需要增强”。
3. 读取 T-012 的 deliverable 措辞库和合成报告，提取 Genes 论文中与“工具功能描述”、“可用性验证”、“局限声明”相关的常见表述模式，作为后续修复开发时可参照的交付物描述参考。
4. 根据需要读取迁移的包代码（resolver、query 入口、index 加载路径）、设计文档、索引构建脚本、查询索引目录，确认每个缺口涉及的具体文件、类、路径和命名约定，避免规划基于猜测。
5. 针对每个缺口，制定具体可执行的修复方案，包括：修复目标、涉及代码/文件范围、预期产出、验收标准、与 Genes 论文可交付物描述的对应关系。
6. 将修复方案组织为分阶段的 G-006 任务建议：先处理阻塞基础层可用性的修复（CAP-03/CAP-07），再处理行为正确性修复（CAP-05），最后处理数值稳健性和论文级打磨（CAP-06）。每阶段明确依赖关系、是否需要人类决策、以及完成后可解锁的后续工作。
7. 为每个阶段的修复任务建议对应的 Genes 论文可交付物描述框架：当该阶段完成后，论文中应使用什么样的措辞描述该能力，参考 T-012 的 wording 模式。
8. 产出中文修复阶段规划报告，包含：每个缺口的技术诊断、分阶段任务建议、阶段间依赖、Genes 论文措辞对齐、以及需要人类决策的阻塞点。

## Constraints
- 本 task 是 planning task，不执行任何代码修改、索引修复、矩阵重新生成或运行测试。
- 不修改迁移资产、T-013 产物、T-007 产物或 T-012 产物。
- 规划应建立在 T-013 和 T-007 的已知证据上，不要假设缺口可以通过“重新运行旧脚本”自动修复。
- 每个修复方案的验收标准必须具体可测，不能是“改善了”、“优化了”。
- 阶段建议必须考虑轻量 Genes 投稿路线：优先修复那些能支撑论文主图和主表的功能，延后非核心或纯展示性功能。
- 规划中不得声称 PxFquery 具有尚未验证的能力。
- 所有产出在 T-023 目录内，不写入其他 task 或最终交付物目录。

## Failure Stop
- T-013 失败清单或能力状态矩阵不可读。
- T-007 开发状态报告不可读，无法建立修改背景。
- 某个缺口的根因无法从现有证据中判断，且无法通过只读方式确认。
- 包代码结构混乱到无法规划合理修改路径，且无设计文档可参考。
- 生成的 prompt、资产规则和文件系统状态矛盾。

## Notes
T-023 是 G-006（algorithm version development）的第一个 task。它的产出将直接指导后续 G-006 执行任务的设计。本 task 应确保后继执行 AI 能从规划报告中直接获得清晰的工作任务定义，不需要重新理解 T-013 的全部证据。
