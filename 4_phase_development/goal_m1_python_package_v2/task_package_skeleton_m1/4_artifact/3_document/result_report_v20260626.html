2. 项目背景

PxFquery 是一个在 macOS 上重启的 LINCS 扰动-功能分析生物信息学项目。其科学方向涵盖正向查询（扰动加生物上下文映射到功能响应）、反向查询（功能目标加生物上下文映射到候选扰动）、以及基于证据的精确匹配与代理匹配检索。该项目目前正处于从遗留 Windows 时代目录树向受控现代工作区全面转型的过程中。T-044 是 goal_m1_python_package_v2 目标序列的第一个开发阶段任务，它的直接前置是 T-007 开发状态报告——T-007 完成了对旧代码库的资产盘点、模块边界划定和遗留代码评估，而 T-044 将这些文档层面的结论落实为一个可直接运行、可 pip 安装的 Python 包骨架。本任务不涉及科学算法实现、不涉及数据加载或索引构建、不涉及 LLM 集成。它的唯一产出是一个结构化的空骨架，供后续 8 到 12 个实现任务在其内部填充代码。

3. 核心结果

交付的包骨架采用 src-layout 结构，包名 pxfquery（由 T-007 锁定，不可变更），版本号 0.1.0，构建系统选用 hatchling，Python 最低版本要求 >=3.10。src/pxfquery/ 下共包含 8 个子包模块：core.py 定义了 PxFquery 主类（构造函数接受可选 config 字典，不含功能方法）；data/loader.py 提供了 DataLoader 占位类；query/forward.py 与 query/reverse.py 分别定义了正向和反向查询类的骨架结构（各附带一个 Result 类）；index/ 下包含 cellline_index.py、drug_index.py、gene_index.py、function_index.py 四个独立的索引存根文件；llm/prompts.py 包含 6 个提示构建函数存根；viz/plots.py 包含 3 个绘图函数存根；cli/__init__.py 作为未来 CLI 入口的纯占位符保留。

三轮导入烟雾测试全部通过：import pxfquery 正常执行且 __version__ 输出 0.1.0；from pxfquery import PxFquery 成功返回 PxFquery 类对象；所有 8 个子包逐层导入成功，每层的类名和函数名符合预期。测试证据已记录在 4_artifact/2_import_smoke/smoke_test_v20260624.txt 中。

4. 项目价值

T-044 交付的包骨架是 PxFquery 项目所有后续开发工作的底部基础设施，在物理结构和元数据两个层面上锁定了项目的包组织方式。从物理结构看，骨架确立了 src-layout 作为项目惯例，定义了 core/data/query/index/llm/viz/cli 的模块划分方式，并为每个模块提供了 import-safe 的占位代码作为实现起点。从元数据看，pyproject.toml 声明了包名 pxfquery（不可变更）、版本 0.1.0、Python 最低版本要求 >=3.10，这些声明将在后续所有任务中被继承。没有这个骨架，后续的 DataLoader 实现、ForwardQuery 和 ReverseQuery 引擎、四个索引组件的构建、LLM 提示词管线、viz 可视化工具和 CLI 入口都将缺乏一致的结构基座——每个实现任务将自行决定目录结构和导入路径，导致项目碎片化。骨架的可复用性被明确设为第一优先级——即使后续某个实现任务完全失败，这个骨架仍可作为项目包结构的标准化文档被保留和引用。此外，骨架的零依赖设计（不要求 numpy、pandas、anndata、openai 等任何运行时库）意味着 CI 系统、文档生成器、打包测试等自动化工具可以直接 import 它而不需要安装沉重的科学计算栈。

6. 后续使用方式

后续 M1 开发任务的标准工作流程如下：第一步，将 4_artifact/1_package/pyproject.toml 和 4_artifact/1_package/pxfquery/ 复制到新任务的 working directory 中。第二步，在 pyproject.toml 的 [project] 下按需添加运行时依赖声明（例如 numpy、pandas、anndata、openai 等），这些依赖当前骨架均未声明。第三步，在各存根模块中填充实际实现代码——填充顺序建议为：先 data/loader.py（数据加载层是查询功能的前提条件）、再 index/ 下四个索引模块（查询引擎需要索引数据结构的支持）、再 query/forward.py 和 query/reverse.py（核心正向和反向查询逻辑）、再 llm/prompts.py 和 viz/plots.py（增值功能层）、最后 cli/（面向终端的用户入口）。第四步，在任务目录下执行 pip install -e . 或 python -c "import pxfquery; print(pxfquery.__version__)" 验证骨架完整性。

7. 边界与风险

使用者需注意以下六项限制。第一，本骨架不包含任何运行时依赖声明，后续任务在添加 numpy、pandas、anndata、openai 等依赖后必须相应地更新 pyproject.toml，否则 pip install 不会自动安装这些库。第二，所有存根的方法体为空（仅含 pass 或 docstring），在任何存根方法上调用会返回 None，使用前必须先填充实际实现。第三，pyproject.toml 的 long_description 引用 README_TASK.md 文件，该文件在任务目录下存在但在项目根目录下不一定存在——这仅影响 pip install -e . 的 README 渲染，不影响 pip install . 或 import 功能。第四，T-044 明确未从遗留代码库迁移任何实现代码，如果需要复用旧代码库中已有的算法逻辑（例如 legacy code/pxfquery_package/ 下的已有类或函数），必须由专门的迁移任务完成，不可直接复制。第五，版本号当前为 0.1.0，后续任务在添加实质性功能后应遵循语义化版本规范进行递增。第六，骨架的包名 pxfquery 和 src-layout 结构不可变更，任何变更都需要在项目协议层面重新协商。
