1. 任务意图

T-044 是 goal_m1_python_package_v2 目标序列中的第一个开发任务，其核心使命是为 PxFquery 项目构建一个全新的、干净的 M1 Python 包骨架。具体而言，需要在任务工作目录下创建 pyproject.toml 构建配置文件，以 src/pxfquery 的 src-layout 组织包目录结构，填充最小化元数据声明，编写 import-safe 的模块存根，并提供完整的导入烟雾测试通过证据。

这一任务之所以必要，是因为 PxFquery 项目正处于从遗留 Windows 时代目录树向受控现代工作区转型的关键阶段。T-007 开发状态报告已经完成了对旧代码库的资产盘点和模块边界划定，但那些结论目前只存在于文档中，尚未物化为一个可 pip install、可直接 import 的 Python 包。T-044 正是将 T-007 的盘点结论落实为物理包结构的关键一步——没有这个骨架，后续所有 loader、query、index、LLM 集成、viz 可视化和 CLI 入口的实现任务将缺乏一致的结构基座。

本次执行严格依赖三份来自 T-007 的已验收资产作为输入依据。第一份是 A-001 开发状态报告（路径 4_artifact/2_persist/pxfquery_development_state_report_v20260617.md），它锚定了规范的包名称为 pxfquery，并划定了 core、data、query、index、llm、viz 六大模块的边界划分方式。第二份是 A-002 模块资产状态矩阵（路径 4_artifact/5_table/pxfquery_module_asset_status_matrix_v20260617.csv），该矩阵以逐模块粒度标注了每个组件的实现状态——哪些功能已有遗留实现、哪些尚不完整、哪些属于纯历史遗留，这一信息直接决定了存根编写范围的取舍。第三份是 A-003 开发阶段交接文档（路径 4_artifact/2_persist/pxfquery_development_phase_handoff_v20260617.md），它额外提供了 D001 包设置范围的推荐标准、验收条件列表，以及一条关键禁令：不得复制 main.py。

3. 实际执行过程

执行过程按协议拆分为四个步骤依次完成。第一步，读取上述三份 T-007 输入资产，逐项核对：确认包名 pxfquery 为唯一选项、确认六大模块的划分方式、确认跳过遗留实现代码迁移、确认 main.py 不得出现。第二步，在任务工作目录创建 pyproject.toml：构建系统选用 hatchling（而非 setuptools），因为 hatchling 的配置全部集中在一个 pyproject.toml 文件中、对纯存根包更轻量、且符合当前 Python 打包生态的主流推荐；包元数据声明 name=pxfquery、version=0.1.0、requires-python>=3.10；包发现模式采用 src-layout；不声明任何运行时依赖。

第三步，创建 src/pxfquery/ 目录及其下全部子包结构。具体产出包括：顶层 __init__.py 设置 __version__ = "0.1.0" 并从 core.py 重新导出 PxFquery 类；core.py 定义 PxFquery 类（构造函数接受可选 config 字典，无功能方法体）；data/loader.py 定义 DataLoader 占位类；query/forward.py 和 query/reverse.py 分别定义 ForwardQuery、ForwardResult、ReverseQuery、ReverseResult 骨架类；index/ 子包下四个独立索引文件各定义一个 Index 类；llm/prompts.py 定义 6 个提示词构建函数存根；viz/plots.py 定义 3 个绘图函数存根；cli/__init__.py 作为空占位符保留。所有存根类的方法体仅包含 pass 或 docstring，确保在不安装任何第三方库的前提下 import 成功。执行脚本 3_execution/create_skeleton.sh 使用 mkdir、cat 和 python -c 命令完整记录了上述每一步。

第四步，运行三轮导入烟雾测试：测试 1 执行 python -c "import pxfquery; print(pxfquery.__version__)" 预期输出 0.1.0；测试 2 执行 python -c "from pxfquery import PxFquery" 确认类导入成功；测试 3 逐子包验证 data、query、index、llm、viz、cli 全部可导入且暴露的类名/函数名正确。三轮测试均通过，退出码为 0。

4. 关键判断与证据

执行过程中出现了三个值得记录的关键判断。第一，构建系统在 hatchling 与 setuptools 之间的选择：hatchling 被选中，因为它可以用单个 pyproject.toml 完成全部配置，无需 setup.py 或 setup.cfg，这对一个纯存根骨架来说更为简洁。第二，__init__.py 的导出策略：顶层 __init__.py 主动从 core.py 重新导入 PxFquery 类，使得协议验收条件中 "from pxfquery import PxFquery 应成功" 能够直接满足。第三，存根的粒度控制：存根类和方法仅使用 pass 打住，不包含任何实际逻辑，也不导入任何外部模块——这一策略确保了在不安装 numpy、pandas、anndata、openai 等任何运行时依赖的情况下，整个包能够干净地 import。

导入烟雾测试证据文件位于 4_artifact/2_import_smoke/smoke_test_v20260624.txt，完整记录了三条测试命令的输出内容。测试 1 输出 pxfquery.__version__ 为 0.1.0；测试 2 确认 from pxfquery import PxFquery 返回了 ；测试 3 逐子包验证通过，无模块缺失、无导入异常。三条测试结果均标注 PASS。
