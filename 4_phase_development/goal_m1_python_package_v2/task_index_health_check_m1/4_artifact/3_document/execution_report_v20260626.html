一、任务意图

T-045 的任务定位是审计而非重建。在 M1 里程碑中，查询索引（来自 T-021 standard-resources）是 forward query 和 reverse query 的基础数据层。如果索引存在格式损坏、关键字段缺失或邻居图空洞，后续的 T-047 加载器加固和 T-042 演示用例都会在错误的数据地基上展开。因此本任务在加载器硬化之前，对所有 10 个 M1 相关索引逐一执行 JSON 可读性检查、模式记录、必需键验证、邻接图完整性评估，以及实体覆盖率分析。输出一份机器可读的健康摘要（JSON）和两份人工可读报告（MD 与 HTML），为 T-047 提供配置依据，同时明确哪些索引可以直接使用、哪些需要加载器侧做解包适配。

二、输入资产与依据

本任务使用 T-021 标准资源集（D-004）下放的 10 个索引文件，存放于 3_resource/standard/ 目录。核心索引包括：cellline_index.json（240 个细胞系名称）、drug_index.json（5958 条药物别名→BRD 映射）、gene_index.json（78061 条基因条目，含 symbol/gene_type/in_matrix 三字段）、function_index.json（91 个功能术语，50 Hallmark + 41 3CA MPS）。可选索引包括六个邻居图和精简索引（drug_neighbors、gene_neighbors、gene_neighbors_simple、gene_index_simple、cellline_neighbors、cellline_tree），以及一个字段语义参考文件 data_description.yaml。实体覆盖率分析方面，由于 T-042（contract_and_demo_spec_m1）尚未执行，本任务使用 T-013 历史演示证据作为代理，提取了 EGFR、A549、HALLMARK_APOPTOSIS、HALLMARK_MYC_TARGETS_V1 四个代表性实体进行交叉检查。

三、实际执行过程

首次执行于 2026 年 6 月 24 日由 AGT-002 完成，共 7 个步骤全部通过。Step 1 对四个核心索引逐个用 Python json.load 解析，确认全部为有效 JSON，并记录了文件大小和元素数量。Step 2 逐索引检查 M1 必需键：cellline_index 使用单键 valid_cells 包裹 240 个名称；drug_index 中 98% 以上的值以 BRD 前缀开头，但缺少反向 BRD→别名映射；gene_index 的三个字段齐全但字段名与规范不一致（symbol 而非 gene_symbol，无 ensembl_id）；function_index 的 91 个术语嵌套在 meta 字典内，结构非扁平，且无 category 字段。Step 3 检查了六个可选索引，所有邻居图的边基数为统一的 50 条，cellline_tree 只有三个扁平键，不是层级树结构。Step 4 确认 T-013 演示实体全部存在。Step 5-7 分别输出 index_health_summary.json（239 行，有效 JSON）、index_health_report.md 和 gap_notes.md。

四、关键判断与证据

核心判断有三条。第一，所有 10 个索引均可解析且数据完整，没有空索引、损坏 JSON 或零条目的退化图，因此整体判定为 M1 就绪。第二，识别出 4 个非阻塞性警告：function_index 的非标准结构要求加载器必须做 meta 解包；gene_index 的字段名需在查询代码中对齐；cellline_tree 的扁平化限制了基于本体的代理扩展；function_index 缺少 category 字段，Hallmark 与 3CA MPS 的区分隐藏在 source 字段的值中。第三，6 个结构缺口中有 2 个为外观性问题（cellline_index 的包装键和 drug_index 无反向映射），不影响 M1 功能。证据全部来自实际的 JSON 解析结果和字段计数，数字已在 index_health_summary.json 中固化。
