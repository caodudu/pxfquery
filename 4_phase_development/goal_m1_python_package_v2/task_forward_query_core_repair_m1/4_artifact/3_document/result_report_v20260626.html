T-059 forward_query_core_repair_m1 结果报告

生成日期: 2026-06-26

1. 一句话结论

T-059 为被阻塞的 T-048 交付了同层修复替换：一个可运行的 M1 前向查询核心包，加上一个任务本地合成修复夹具，使得 T-042 合约要求的 EGFR/A549/xpr 正向演示能够返回 found=true，同时保留了完整的无命中结构化 JSON 行为和 CLI 入口。

2. 项目背景

PxFquery 是一个基于 LINCS 的扰动-功能生物信息学工作流，支持通过 forward query（扰动+生物上下文→功能响应）和 reverse query（功能目标+生物上下文→候选扰动）来查询药物和基因诱导的功能程序。T-042 为本项目的 M1 里程碑定义了公共 API 合约和正向演示用例，其中 EGFR/A549/xpr 是必须通过的阳性用例。T-046 选定的夹具资产中恰好缺少该用例所需的观测行，导致 T-048 无法满足合约要求而受阻。T-059 在此背景下作为修复任务启动，目标是交付一个可运行的前向查询核心，同时用明确标记的合成数据桥接合约空缺。

3. 核心结果

全部 11 项合约验证断言通过。正向演示 EGFR/A549/xpr 返回 found=true，包含 4 个以上 top_activated 基因集评分（如 HALLMARK_ADIPOGENESIS 4.03、HALLMARK_APOPTOSIS 2.47）和 3 个以上 top_suppressed 评分（如 MP40 PDAC-related -6.68）。无命中演示针对 UNKNOWN_GENE_XYZ999 返回了结构化的 PerturbationNotFound JSON 对象，包含 perturbation、matrix_type、query_type、suggestions 和 _evidence 块，无 Python 回溯。CLI 命令 pxfquery forward EGFR --cell-line A549 输出有效 JSON 且返回码为 0。修复清单 forward_repair_manifest_m1_1.yaml 正确标注了 synthetic_repair 来源。所有上游产出（T-042、T-043、T-044、T-046、T-047）均未被修改。核心证据文件 forward_query_positive_demo_evidence_v20260624.json 和 forward_query_no_hit_evidence_v20260624.json 已写入 4_artifact/2_persist/ 供验收检查使用。

4. 项目价值

T-059 解除了 T-048 阻塞对下游 M1 前向查询工作的影响。项目现在拥有一个可运行的前向查询核心包，包含 API 和 CLI 入口、合约兼容的 JSON 输出格式、正确的无命中行为以及清晰的 provenance 标签。下游任务（如 M1 集成测试、演示脚本编写、反向查询准备）可以直接以 T-059 包为基础，无需等待上游夹具修改或契约重谈。同时，本次修复严格保持了上游已完成工件的完整性，未引入跨任务污染。

6. 后续使用方式

下游 M1 任务应使用 T-059（而非 T-048）作为前向查询核心的权威来源。导入方式为 from pxfquery.api import forward_query 或通过 CLI 命令 pxfquery forward。修复夹具应通过 M1FixtureLoader 加载，manifest 路径指向 forward_repair_manifest_m1_1.yaml。任务本地修复夹具仅适用于 T-059 范围的演示和测试；使用时应始终保留 synthetic_repair 标签。完整的资产注册信息与复用指引见 4_artifact/registry.yaml 中各条目的 description、usage 和 lineage_anchor 字段。

7. 边界与风险

修复夹具中的 EGFR/A549/xpr 内容是 synthetic_repair 性质的合约桥接数据，并非来自 LINCS 原始数据或任何真实生物学实验。该数据仅用于使 EGFR/A549/xpr 正向演示在合约层面通过，不提供任何生物学排序有效性或全资源覆盖保证。切勿将 T-059 修复夹具视作 T-043/T-046 原生内容的扩展。如果未来需要真实的 EGFR/A549 观测数据，应通过专门的数据获取任务补充，而不是依赖本修复基底。本报告仅呈现任务结果与使用指引，未修改任何核心交付物、代码、数据或分析结果。
