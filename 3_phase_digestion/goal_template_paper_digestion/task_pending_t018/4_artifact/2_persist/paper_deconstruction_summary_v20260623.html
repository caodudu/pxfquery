Genes 介绍写作模式归纳：
1. Intro 字数区间 ~700-2000，说明 Genes 对长度容忍度大。
2. 起手式：一个具体生物学问题或应用需求（不要空谈 AI 或 big data）。
3. Gap 写法："已有方法做了 X，但 Y 还不够好／没解决 Z" → "to address this, we propose..."
4. Portal 类论文不需要方法创新 Gap，可以用"缺工具"作为 Gap。

Genes 图摆放模式归纳：

2. 后续图按"验证维度逐级加深"排列：内部性能 → 外部对比 → 应用案例 → 生物学解释。
3. 图的类型组合标配：架构图 1 + 性能/对比图 2-3 + 案例/UI图 1-2。

Genes 风格要点总结（供 PxFquery 写作参考）

1. 题名

"工具名: 功能描述 + 应用场景". 例：OHDLF: A Method for ... and Its Application in ...

给工具起一个可记忆的名字（OHDLF/DTVF/CrossMP/GENet/StrainIQ），不要纯描述性标题。

2. 介绍

从具体生物学问题切入，锚定一个应用场景。Gap 用"现有方法有X不足"而非"这个领域没人做过"。

700-2000 字均可，关键是把"为什么需要这个工具"说清楚。

3. 方法

详细描述模型/算法/架构。844-2143 字的 Methods 在 Genes 是常规长度。

明确标注章节标题（Materials and Methods），方便同行定位。

4. 结果

短段落密集推进（30-80段）。从内到外验证：先自己数据 → 再对比其他方法 → 最后真实案例。

每段配图表引用。1000-3500 字 Results 均可接受。

5. 图

4-6 张图是标准。图1=架构/流程图。后面按性能→对比→案例排列。

每张图回答一个具体问题。架构图 + 对比表 + 案例图 是 Genes 的最低图包配置。

6. 交付描述

固定描述：用户输入什么 → 系统做什么 → 输出什么 → 怎么验证 → 在哪获取。

不要含糊的 availability 声明。给出明确的 URL/仓库/数据链接。

7. 弱点管理

在讨论中主动承认：样本规模、外部验证不足、单数据集、没有API/命令行等。

Genes 接受这些弱点，但需要在 Discussion 中提及。

8. 工作量感

靠多图表 + 多验证维度 + 短段落密集论述来营造"做了很多事"的感觉。

案例应用比纯方法描述更有效：用真实数据演示工具价值。
