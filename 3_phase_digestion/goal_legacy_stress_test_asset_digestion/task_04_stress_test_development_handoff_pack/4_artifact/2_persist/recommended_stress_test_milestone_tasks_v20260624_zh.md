## 概述

以下 7 项任务构成了 PxFquery 压力测试开发的推荐里程碑。每项任务均以前序消化证据为依据（T-055 来源映射、T-056 场景清单、T-057 复用边界），并与 T-007 开发状态建议保持一致。

该任务序列以 T-007 D001（建立当前包工作区）为入口前置条件 —— 在当前项目中包可被导入之前，压力测试里程碑无法启动。

## ST-M01：建立压力测试工作区与资产访问

**目标**：在当前项目中创建一个压力测试工作区，可访问所有就绪可复用的资产和已注册的查询索引，且不复制或修改遗留的扁平库文件。

**预估工作量**：小型（1-2 个工作时段）
- 在开发阶段中创建一个压力测试模块或目录
- 以软链接或引用方式接入已迁移的查询索引（`data/query_indexes/`），作为只读运行时索引
- 以软链接或引用方式接入 10 份直接引用报告（M-0239、M-0291、M-0277、M-0275、M-0267、M-0243、M-0244、M-0290），用于读取证据
- 复制解析器源代码（`resolver.py`、`forward.py`、`reverse.py`）作为权威参考；不得修改
- 记录哪些待重写脚本（交接包第 4 节）已就位待移植
- 验证已标注 `function_index.json` 的缺失情况，并已备有占位处理方案

**前置依赖**：T-007 D001（当前包工作区）
- 压力测试工作区必须建立在可导入的 PxFquery 包之上

**理由**：全部 11 个待重写脚本（T-057 §2.2）在移植开始前都需要当前项目工作区。T-007 Gap #4 指出旧工作区路径是主要障碍。本任务在不触碰扁平库的前提下创建干净的目标工作区。

**锚定证据**：
- T-057 §3.1："每个脚本都使用旧工作区路径"
- T-007 Gap #1："包的可运行性未经验证"

## ST-M05：移植 LLM 稳定性评估器（可选，外部依赖）

**目标**：将 LLM 稳定性检查器移植为可选的 CI 外测试，并使用当前 LLM provider 产生一次全新的稳定性测量。

**预估工作量**：中小型（1-3 个工作时段）
- 移植 `M-0377_check_llm_stability.py`（需重写，T-057），需：
  - 当前 LLM provider 配置
  - 3-5 个案例（不仅是 3 个）以提升统计分辨率
  - 每个案例 3 轮
  - 输出归档（该脚本当前形式下不产生输出）
- 针对 SC-011（EGFR 抑制剂）、SC-012（NSCLC）、SC-024（模式分歧案例）运行，外加 1-2 个行为良好的精确案例作为对照
- 记录稳定率并与 M-0267 基线（6/9）比对
- 若稳定性退化（例如 <50%）：标记为升级风险
- 若稳定性改善（例如 >80%）：记录但**不得**在未进一步验证前升级论文论断
- **不得**纳入 CI；此为可选手动测试，需要 LLM API 访问权限

**前置依赖**：ST-M01、ST-M02、ST-M03（可选：若 mock 确定性测试通过，可在 ST-M01 之后运行）
- 需要在当前工作区中配置 LLM API 凭证

**理由**：LLM 稳定性是所有前序任务中记载最为一致的风险：T-055 §5.3、T-056 SC-011/SC-012/SC-024、T-057 §2.1（M-0267）、T-007 Gap #3。M-0267 的 6/9 稳定性是唯一正式的测量。T-007 更为审慎的论断建议"确定性检索是科学基石"——一次全新的稳定性测量可确认或更新该立场。可选/外部依赖的定位反映 T-057 的建议："不纳入 CI。"

**锚定证据**：
- T-057 §2.2：M-0377 "作为可选外部依赖测试移植"
- T-007 Gap #3："LLM 路径不稳定且缓慢；以 hybrid_fast 为默认"
- M-0267：6/9 基线用于比对
- 交接包第 4 节风险："真实 LLM 依赖（无 mock 回退）——中等"

## ST-M07：压力驱动的案例研究与风险登记册

**目标**：将所有压力测试里程碑结果综合为一份整合的案例研究演示，以及一份更新后的风险登记册，以便移交至论文阶段任务。

**预估工作量**：中型（2-4 个工作时段）
- 选择一个证据充分、干净的正向案例（推荐：SC-004/SC-017——A549 中的 EGFR 或 KRAS，EXACT，含确定性匹配）
- 选择一个反向案例（推荐：SC-006——A549 中激活凋亡，禁止代理），前提是 ST-M06 产生了可用结果
- 产出最小演示走查：输入 → 解析器路径 → 命中层级 → 前 N 个功能程序/扰动候选 → 证据包元数据
- 运行从 ST-M04 推迟的高风险场景，以确认预期的失败行为：
  - SC-001（多基因正向）——预期 FAIL
  - SC-003（药物+基因组合）——预期 FAIL
  - SC-011（通用药物）——预期 INCONSISTENT（依赖模式）
  - SC-022（多药物多上下文）——预期 FAIL
  - SC-025（always_llm 延迟）——预期 LATENCY_ISSUE
- 为每个失败记录：预期是什么、实际发生了什么、映射到哪个风险缺口
- 用最新证据更新 T-007 A-008 的风险登记册：
  - function_index.json 重建是否成功 → 解决 Gap #2
  - 确定性矩阵结果是否复现 → 确认 Gap #1 的解决或上报
  - LLM 稳定性是否优于 6/9 → 更新 Gap #3
  - 药物通用查询是否仍不一致 → 更新 Gap #8
- 将所有结果制品（演示输出、风险登记册 v2）注册为当前项目资产

**前置依赖**：ST-M01 至 ST-M06
- 汇总所有前序任务的结果

**理由**：T-007 D005 建议选择"一个易于解释的窄生物学演示"用于 Genes 风格案例研究。T-056 的场景清单提供了候选池——通过的场景（SC-004、SC-005、SC-017）自然是合适的演示内容。预期失败的场景（SC-001、SC-003、SC-011、SC-022、SC-025）的运行目的不是"修复"，而是产出诚实的风险证据，以便论文将其框架为"已知局限性"。

风险登记册的更新搭建了一座从本压力测试里程碑通往下一个开发或论文阶段的清晰移交桥梁。

**锚定证据**：
- T-007 D005："选择一个具体的 Genes 风格案例研究"
- T-056：29 个场景，含 6 个预期 FAIL
- T-007 A-008：待用压力测试证据更新的缺口与风险清单 v1
- M-0243 known_risks：6 个风险待压力测试后重新核验
