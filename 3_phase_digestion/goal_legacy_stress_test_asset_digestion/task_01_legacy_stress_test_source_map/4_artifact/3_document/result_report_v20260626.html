结果报告 — T-055 01_legacy_stress_test_source_map

任务： 遗留压力测试资产源映射

日期： 2026-06-26

状态： 已交付

1. 一句话结论

本任务为 PxFquery 迁移平面库中约 160 项遗留压力测试相关资产建立了结构化源映射，填补了从遗留资产到当前验证任务之间的导航缺口。

2. 项目背景

PxFquery 是一个 macOS 托管的 LINCS 扰动-功能分析生物信息学项目，从旧 Windows 目录树迁移了大量代码、数据和报告。在消化阶段中，T-001 完成了遗留语义消化，T-002 完成了平面资产迁移，T-007 完成了开发现状消化。本任务（T-055）是 G-005 目标下的第四项消化任务，聚焦于从迁移资产中识别和编目与压力测试相关的材料。项目后续需要设计验证套件来确保解析器、查询索引和 GSEA 管线的正确性，而本任务正是验证套件设计的前置依赖。

3. 核心结果

源映射覆盖了 7 个目标目录中的约 160 项候选资产，按 9 类压力测试相关性进行归类。验证脚本方面，code/index_builders/ 中的 6 份 Python 脚本是构建验证套件的最强起点，其中 M-0386_test_forward_matrix.py 实现了 7/7 确定性的模拟命中级别测试。验证报告方面，共 57 份报告中有 15 份已与 T-007 索引重叠，约 42 份为新编目。解析器源码（resolver.py 计 1072 行）包含了 L1 精确匹配到 L4 双代理匹配的四层搜索策略及其边界处理逻辑。查询索引方面，9 个运行时 JSON 文件已定位，但 function_index.json 缺失是最严重的运行时缺口。GSEA 评估方面，54 份脚本和 6 份大型结果表（各 244-372MB）提供了功能评分管线的验证基础，但均依赖 HPC 环境和 SLURM 调度器。性能方面，always_LLM 模式（167.3s/4 查询）比 hybrid_fast v3（0.825s/3 查询）慢约 200 倍，llm_parse_intent 占 always_LLM 总延迟的 70%（117.1s）。LLM 稳定性方面，6/9 的成功率意味着对 LLM 的输出应当采取审慎态度。

4. 项目价值

本任务的核心价值在于它将弥散的遗留资产转化为一份可直接导航的候选目录。如果没有这份源映射，后续任务需要自行在平面库中逐一翻阅约 160 项资产，而且容易遗漏关键文件或重复编目 T-007 已有的记录。通过本任务，验证套件设计者可以在 30 分钟内定位到最有效的起点（M-0386）、最需关注的缺口（function_index.json）、最需审慎对待的风险（LLM 6/9），以及最需要消重的区域（脚本重复对、套件运行变体）。这份映射同时也是 G-005 目标中"不对遗留根目录进行直接扫描"这一协议约束的具体贯彻手段。

5. 交付物导读

应首先阅读 legacy_stress_test_source_map_v20260624.md（D-001），这是一份 365 行的结构化 Markdown 文档，包含完整的分类目录（第 2 节，10 个子节）、与 T-007 的交叉引用对照（第 3 节）、8 项缺失/不明确线索的记录（第 4 节），以及对后续任务的 7 条使用指南和 4 项注意事项（第 5 节）。stress_test_candidate_asset_index_v20260624.csv（D-002）是 124 行的机器可读索引，包含 category、migrated_path、original_path、asset_type、relevance、runnable_claim、T-007_cross_ref、notes 共 8 列，可用 DataFrame 直接加载并筛选。

6. 后续使用方式

建议按以下优先顺序使用本任务产出。第一步是验证套件设计，从源映射第 2.1 节的 6 份验证脚本出发，复制到当前开发任务中，将工作区路径更新后以 mock provider 先行运行。第二步是缺口修复，通过 M-0373_build_function_index.py 重建缺失的 function_index.json。第三步是基线比对，以 M-0386 的 7/7 确定性测试作为主要回归依据。第四步是性能建模，参考 M-0277 和 M-0275 的计时数据设定模式切换策略。第五步是 LLM 风险评估，引用 M-0377 和 M-0267 的 6/9 成功率来撰写保守的 LLM 声明。后续的验证任务应同时参考本映射（覆盖脚本、索引、GSEA）和 T-007 证据索引（覆盖已审验的验证报告），以形成完整的验证体系。

7. 边界与风险

最重要的边界是所有脚本均标记 runnable_claim: false——它们包含遗留工作区路径假设，在当前环境中不可就地运行。function_index.json 的缺失意味着完整的解析器验证流程受阻，必须先重建该运行时文件。GSEA 评估脚本依赖 SLURM 集群环境和 scanpy、gseapy 等 HPC 级依赖，在 macOS 上需要寻找等效替代或容器化方案。GSEA 结果表中的 6 个 CSV 文件是符号链接占位符（各 244-372MB），其目标文件是否仍然可访问需要验证。脚本重复对（M-013x 与 M-034x/035x 系列）和时间戳变体（M-0266 衍生出 6 份副本）在使用前应先行消重。遗留的 M-0298 main.py 包含大量空实现方法，属于历史文件，不应纳入验证范围。
