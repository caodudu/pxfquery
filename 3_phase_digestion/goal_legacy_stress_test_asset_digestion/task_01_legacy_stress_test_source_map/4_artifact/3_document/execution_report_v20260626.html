1. 任务意图

本任务的目标是为已迁移的遗留材料创建一份源映射，筛选出与 PxFquery 压力测试、复杂查询、解析器验证、严格边界条件以及旧验证脚本/报告相关的资产。PxFquery 项目从旧 Windows 时代目录树中迁移了大量遗留代码、数据和报告，但缺乏一份结构化的指南来告诉后续任务哪些资产可用于构造验证套件。本任务充当这一桥梁：它不执行任何脚本，也不做验证，而是生成一份候选资产目录，使得后续的评估和验证任务可以在不接触遗留根目录的前提下开展工作。

2. 输入资产与依据

任务依据九项前置资产运转。A-001（平面资产库）是浏览主体，覆盖了 7 个高优先级目录。A-005、A-006、A-007 来自 T-007（开发现状消化），提供了已有的 15 条验证证据索引以及已知差距和风险清单，用于避免重复编目。A-002（迁移清单）和 A-009（未迁移报告）帮助追溯每个文件的遗留来源路径和未被迁移的原因。A-003 和 A-004 提供了遗留结构背景和项目起源上下文。A-008 提供了中文平面库结构说明，辅助导航。

3. 实际执行过程

执行流程分四步。首先读取 T-007 的三份交付物，建立已知验证环境的基线。其次阅读迁移清单和未迁移报告，定位压力测试相关的条目。随后逐一浏览平面资产库中所有 7 个目标目录——reports/validation_reports/（57 项）、code/index_builders/（19 项）、code/pxfquery_package/query/（5 项）、data/query_indexes/（9 项）、reports/digested_context/（9 项）、code/analysis_scripts/（55 项）、results/gsea_tables/（6 项）。对每项资产，检查文件内容、确定压力测试相关类别、记录迁移路径与遗留来源路径，并与 T-007 进行交叉引用。最终生成约 160 条候选资产的 CSV 索引和一份结构化的 Markdown 源映射文档。

4. 关键判断与证据

最关键的发现是 function_index.json 在迁移后的查询索引中完全缺失，这是最严重的运行时资源缺口——V-004 已标记该问题，本任务确认且无法在平面库中定位该文件，必须通过 M-0373_build_function_index.py 重建。另一项重要发现是 code/index_builders/ 中的六份验证脚本，其中 M-0386_test_forward_matrix.py 提供了最强的验证基线（确定性 7/7 通过率），适合作为主要回归测试。在 LLM 稳定性方面，M-0377 和 M-0267 共同记录了 6/9 的成功率，EGFR 抑制剂和 NSCLC 类查询失败，说明 LLM 的可靠性不宜作为核心主张。性能数据方面，always_LLM 模式（167.3s/4 查询）比 hybrid_fast v3（0.825s/3 查询）慢约 200 倍。此外，GSEA 评估脚本引用了 SLURM 集群路径，在 macOS 环境中的直接可用性有限。所有脚本均标记 runnable_claim: false，符合协议约束——它们包含遗留工作区路径假设，不能在当前环境中就地运行。
