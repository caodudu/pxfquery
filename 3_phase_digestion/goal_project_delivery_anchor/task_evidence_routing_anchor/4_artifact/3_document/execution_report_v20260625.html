T-064 证据路由锚点执行报告

任务意图

T-064 的任务是为 PxFquery 定义 evidence routing 的行为合同。项目不只是要返回一个数值结果，还要解释这个结果是 exact-hit、proxy-hit、no-hit、ambiguous-hit、context-missing 还是 transfer/suggestion。没有这层锚点，后续实现可能把 no-hit 错误地变成模糊命中，把 proxy 结果当成 exact evidence，或者让 LLM 解释替代真实数据证据。

输入资产与依据

执行读取了 A-001 至 A-005。T-007 提供 resolver/proxy 设想、7/7 deterministic matrix 验证和风险；T-013 提供 CAP-05 no-hit false match 与 CAP-07 resolver blocked 等失败证据；T-021 提供 canonical standard resources，包括 3 个 functional matrices、10 个 query indexes 和 metadata tables；T-058 提供 29 个 stress-test scenarios。所有判断都来自这些登记资产，没有扫描上游 task 目录或 legacy root。

实际执行过程

步骤执行内容结果
1整理前置证据中的 exact/proxy/no-hit/LLM/standard-resource 事实。确认六类 route 都可以从现有证据中定义。
2写 route taxonomy 和 acceptance cases。形成 6 类 route、21 个 acceptance cases、决策流和边界说明。
3写 evidence metadata contract。定义 8 个必需 response fields、route-type constraints、LLM 字段和 threshold policy。
4把 T-058 的 29 个 stress-test scenarios 映射到 route types。形成 CSV 映射表，覆盖 exact/proxy/no-hit/boundary/complex/LLM/missing-index 场景。
5登记交付物并写 completion/report。三项核心交付物和两份 HTML 报告均登记在 registry。

关键判断与证据

最关键的判断是 no-hit 必须有显式 threshold guard，不能用无约束 token similarity 或 fuzzy fallback 产生假阳性；proxy-hit 必须暴露 proxy_chain 和 confidence，不能伪装成 exact-hit；LLM 只能辅助解析、解释和 suggestion，不能替代 matrix/index evidence。T-058 的 29 个场景中没有独立 ambiguous-hit 和 transfer/suggestion 场景，因此本 task 明确记录这些是由 no-hit/context-missing 等场景间接推导出来的未来验收缺口。

交付物清单

  • evidence_routing_route_taxonomy_v20260625.md：六类 route 与 acceptance cases。
  • evidence_routing_metadata_contract_v20260625.yaml：route response 的机器可读字段合同。
  • evidence_routing_stress_test_mapping_v20260625.csv：29 个 stress-test scenarios 到 route expectations 的映射。

边界与未完成事项

本 task 没有写代码、没有运行压力测试、没有修复 function_index runtime path，也没有证明 resolver 已经能执行这些 routes。它交付的是 specification/contract anchor。后续 M3 或 stress-test task 必须用这里的 route taxonomy 和 metadata contract 去检验实现，而不能把这份设计当成 runtime pass。
