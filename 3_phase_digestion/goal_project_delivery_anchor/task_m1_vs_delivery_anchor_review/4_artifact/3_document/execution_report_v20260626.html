T-065 M1 vs Delivery Anchor Review — 执行报告

任务意图

PxFquery 项目的交付锚点（T-062 算法包锚点、T-063 LLM Resolver 能力锚点、T-064 证据路由锚点）已在 digestion 阶段完成定义，但此前没有一套正式回溯机制来检查已交付的 M1 里程碑是否真正达到了这些锚点的要求。T-065 就是为此而设的审查任务：它不修代码、不补功能、不改协议，而是以 16 份注册资产为唯一依据，将 M1 的证据逐条对照三个锚点的能力标准，给出受控词汇下的明确分类。这项审查的直接产出是一份机器可读的 gap review、一份能力状态矩阵和一份中文叙事报告，它们共同决定了后续 M2 和 M3 规划的真正起点。

输入资产与依据

本次执行依赖 16 个已注册输入资产，不读取任务目录之外的任何文件。来自 T-053 M1 里程碑的资产包括 milestone report（A-001）、evidence index（A-002）、layered asset map（A-003）和 known gaps（A-004），它们提供了 M1 声称交付的内容及其自认的局限性。来自 T-062 的算法包锚点（A-005）、能力矩阵（A-006）、降级规则（A-007）、审查量规（A-008）和分类词汇（A-009）定义了包层面必须满足的能力标准和证据层级。来自 T-063 的 LLM Resolver 锚点（A-010）、功能设计（A-011）、演示用例目录（A-012）和验收矩阵（A-013）定义了 resolver 行为的不可替代标准。来自 T-064 的路由分类（A-014）、元数据契约（A-015）和压力测试映射（A-016）明确了 exact、proxy、no-hit、ambiguous、context-missing、transfer 六种路径及各路径的证据要求。

实际执行过程

执行分五个阶段进行。第一阶段从 A-001 到 A-004 中提取 M1 明确声称和已证据化的能力，确认其提供 pxfquery 0.1.0 editable install、forward/reverse CLI fixture demo 和基础结构化错误处理。第二阶段对照 T-062 的包级能力矩阵建立 checklist，将 forward/reverse/deterministic query、biological context、metadata 和 standard resource 纳入检查范围。第三阶段单独审查 resolver/LLM 能力，确认 natural-language entry、semi-structured parse、CyHex 配置的 LLM route 和 demo 目录覆盖未被 M1 支撑。第四阶段对照 T-064 逐条检查六条路由和八字段元数据契约，确认 exact 有窄证据，proxy、ambiguous、transfer/suggestion 和完整元数据契约缺失。第五阶段用 T-062 的受控词汇（partial、downgraded、deferred-not-approved、evidence-insufficient）为每条能力标注状态，识别三个未批准的范围收缩实例，并生成 YAML、CSV、Markdown 和 HTML 报告。

关键判断与证据

核心判断是 M1 应分类为 deterministic kernel/substrate，而非完整锚点算法包。M1 已有正向和反向确定性查询的 fixture 级证据、CLI 路由和结构化异常类，覆盖 CAP-FWD-001、CAP-REV-001、CAP-CTX-001 等十条能力为 partial。然而四条能力（CAP-EVD-PROXY-001、CAP-ENTRY-RESOLVER-001、RES-ENTRY-STRUCT-001、ROUTE-PROXY-HIT）被标注为 downgraded，四条（CAP-LLM-001、RES-ENTRY-NL-001、RES-DEMO-001、ROUTE-TRANSFER-SUGGESTION）为 deferred-not-approved，四条（CAP-RES-001、RES-AI-001、ROUTE-AMBIGUOUS-HIT、ROUTE-METADATA-CONTRACT）为 evidence-insufficient。SHRINK-001 至 SHRINK-003 明确指出：把 synthetic exact-only fixture 称为完整包交付、用 CLI 参数代替 resolver entry、用 prompt template 存在代替 LLM 行为，均构成未批准的范围收缩。22 条能力中没有任何一条获得 delivered 或 full 标签，说明 M1 在锚点体系下还远未到终点。

边界与未完成事项

本任务不运行 M1 包的代码验证、不执行单元测试、不修复任何已知 gap、不生成新数据或索引，也不修改 T-053 的 M1 产出物或 T-062/T-063/T-064 的锚点文档。审查基于已注册的 16 个输入资产，如果这些资产中缺少 M1 实际支持但未报告的能力，本次审查不会发现。后续若通过新任务补做了标准资源兼容性或 evidence routing，必须产生新证据并重新对照锚点更新 milestone 状态，不能依赖本报告的缺失项作为永久缺陷。
