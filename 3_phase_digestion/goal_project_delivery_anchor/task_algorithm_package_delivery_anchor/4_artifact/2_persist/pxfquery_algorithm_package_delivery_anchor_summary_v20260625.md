# PxFquery 算法包交付锚点摘要

生成日期：2026-06-25

## 目的

本任务建立 PxFquery 后续算法包里程碑的交付锚点。它的作用不是实现代码，也不是重新运行算法，而是规定未来评审时必须检查哪些能力、需要什么证据、哪些情况属于降级，以及哪些延期必须经过用户明确批准。

核心原则：PxFquery 不能在后续里程碑中被静默缩减为“确定性字典或矩阵查表”。如果里程碑要求 resolver、LLM 辅助、proxy 路由、自然语言或半结构化入口、用户查询转译、fallback 行为，这些能力必须被保留为评审对象。

## 必需能力集合

未来算法包交付至少应按以下能力评审：

| 能力 | 要求 |
|---|---|
| 正向查询 | 扰动 + 生物学背景 -> 功能程序响应，并输出可序列化结果和状态 metadata |
| 反向查询 | 功能目标 + 生物学背景 -> 候选扰动排序，并检查数值稳定性 |
| 生物学背景处理 | 细胞系、谱系、疾病或亚型要参与检索或 proxy 判断 |
| 精确证据路由 | 先尝试 exact match，并在输出中标记 exact 证据 |
| proxy 证据路由 | 在覆盖稀疏时使用细胞系层级、基因邻居、药物邻居或功能别名，并标记 proxy 来源 |
| not-found 路由 | 对不支持或低置信输入安全返回 no-hit/not-found，不能误报为真实匹配 |
| resolver 入口 | 在里程碑要求时，支持自然语言或半结构化输入解析与分发 |
| LLM 辅助 | 在里程碑要求时，使用当前配置 AI 服务进行解析或总结，并有确定性 fallback |
| 确定性 fallback | fallback 必须清楚标记触发原因和路径，不能伪装成主路径成功 |
| 透明证据 metadata | 输出应包含状态、路由、来源、warning、限制说明 |
| 标准资源兼容 | 默认以 T-021 标准资源为当前数据基础，或登记明确的后继资源 |

## 降级规则

运行时 fallback 不等于交付范围降级批准。比如 LLM 失败后使用确定性解析器可以是合理运行行为，但不能因此声称已经交付 LLM 辅助解析，除非里程碑明确接受 fallback-only 范围。

以下情况需要用户明确批准：

1. 删除或延期里程碑要求的正向/反向查询。
2. 把 resolver、proxy 或 LLM 能力改成可选。
3. 用 exact-only 查表替代要求的 proxy 路由。
4. 用直接 API 调用替代要求的用户入口 resolver。
5. 把 LLM 连通性测试当成完整 LLM 解析/总结交付。
6. 因为论文表述要保守，就取消软件里程碑中要求的 resolver 或 LLM 能力。
7. 缺少透明 evidence metadata 仍声称 evidence-aware 检索已交付。

没有用户批准的延期或替代，应标记为 `downgraded` 或 `deferred-not-approved`。

## 评审词汇

本锚点定义了未来里程碑使用的状态词汇：

- `delivered`：有当前证据证明主路径可以工作。
- `partial`：部分工作，但覆盖、稳健性或范围不足。
- `blocked`：资源、配置、账号或依赖阻止运行或评估。
- `failed`：已尝试但结果错误、不安全或不可用。
- `downgraded`：必需能力被移除、弱化或替代。
- `deferred-user-approved`：延期有明确用户批准。
- `deferred-not-approved`：延期没有明确用户批准。
- `out-of-scope`：协议明确排除，不是因为困难才排除。
- `evidence-insufficient`：证据不足，不能接受交付声明。

## 当前证据边界

T-013 证明了正向 exact 查询可工作，反向查询有部分证据但存在数值 warning，not-found 路由曾出现 fuzzy 误报风险，resolver/proxy 在当时被索引缺口阻断。T-021 已重建 `function_index.json`，并提供了验证过的标准资源包。因此后续开发任务应在当前资源基础上重新验证 resolver/proxy/LLM，而不是仅引用旧报告。

本任务没有修改包源码，没有运行算法测试，没有重建矩阵或索引，也没有使用外部来源。
