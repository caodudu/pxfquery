PxFquery 算法包交付锚点摘要

生成日期：2026-06-25

目的

本任务建立 PxFquery 后续算法包里程碑的交付锚点。它不实现代码，也不重新运行算法；它规定未来评审时必须检查哪些能力、需要什么证据、哪些情况属于降级，以及哪些延期必须经过用户明确批准。

核心原则：PxFquery 不能在后续里程碑中被静默缩减为确定性字典或矩阵查表。如果里程碑要求 resolver、LLM 辅助、proxy 路由、自然语言或半结构化入口、用户查询转译、fallback 行为，这些能力必须被保留为评审对象。

必需能力集合

能力要求
正向查询扰动 + 生物学背景 -> 功能程序响应，并输出可序列化结果和状态 metadata。
反向查询功能目标 + 生物学背景 -> 候选扰动排序，并检查数值稳定性。
生物学背景处理细胞系、谱系、疾病或亚型要参与检索或 proxy 判断。
精确证据路由先尝试 exact match，并在输出中标记 exact 证据。
proxy 证据路由在覆盖稀疏时使用细胞系层级、基因邻居、药物邻居或功能别名，并标记 proxy 来源。
not-found 路由对不支持或低置信输入安全返回 no-hit/not-found，不能误报为真实匹配。
resolver 入口在里程碑要求时，支持自然语言或半结构化输入解析与分发。
LLM 辅助在里程碑要求时，使用当前配置 AI 服务进行解析或总结，并有确定性 fallback。
确定性 fallbackfallback 必须清楚标记触发原因和路径，不能伪装成主路径成功。
透明证据 metadata输出应包含状态、路由、来源、warning、限制说明。
标准资源兼容默认以 T-021 标准资源为当前数据基础，或登记明确的后继资源。

降级规则

运行时 fallback 不等于交付范围降级批准。LLM 失败后使用确定性解析器可以是合理运行行为，但不能因此声称已经交付 LLM 辅助解析，除非里程碑明确接受 fallback-only 范围。

删除、弱化、替代或延期里程碑要求的 resolver、proxy、LLM、正向/反向查询、not-found 路由或 evidence metadata，都需要明确用户批准。没有批准的延期或替代，应标记为 downgraded 或 deferred-not-approved。

评审词汇

未来里程碑应使用 delivered、partial、blocked、failed、downgraded、deferred-user-approved、deferred-not-approved、out-of-scope、evidence-insufficient 分类每项能力。

当前证据边界

T-013 证明了正向 exact 查询可工作，反向查询有部分证据但存在数值 warning，not-found 路由曾出现 fuzzy 误报风险，resolver/proxy 在当时被索引缺口阻断。T-021 已重建 function_index.json，并提供了验证过的标准资源包。因此后续开发任务应在当前资源基础上重新验证 resolver/proxy/LLM，而不是仅引用旧报告。

本任务没有修改包源码，没有运行算法测试，没有重建矩阵或索引，也没有使用外部来源。
