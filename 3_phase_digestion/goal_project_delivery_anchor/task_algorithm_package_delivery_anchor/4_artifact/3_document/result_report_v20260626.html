T-062 算法包交付锚点结果报告

一句话结论

T-062 产出了一套完整的算法包交付锚点，将 PxFquery 未来包里程碑的交付边界从模糊的"做出一个能跑的东西"固化为 11 项可逐项检查、可明确分类、不能被静默削弱的能力定义、验收证据和降级规则。任何试图删除 resolver、LLM、proxy、no-hit、元数据或标准资源兼容性的里程碑，都必须显式标注为 downgraded、partial、blocked 或 user-approved deferral，而不能自称 delivered。

项目背景

PxFquery 的历史遗产中包含旧版包代码、MVP 评审报告、标准资源探索成果和零散的未来计划。项目当前面临的核心风险不是"能不能跑通几个查询"，而是"后续里程碑可能为了降低完成难度，只维护能跑通的确定性查询内核，却把用户端的自然语言入口（resolver）、LLM 辅助解析（LLM-assisted parsing/summarization）、稀疏数据时的代理证据路由（proxy evidence routing）、安全空结果路由（not-found routing）、透明结果元数据（evidence metadata）和标准数据格式兼容性悄悄弱化为"以后再说"或"不在当前范围"。

T-062 作为项目 delivery-anchor 目标下的治理任务，其使命就是消除这种静默缩小风险。它不负责实现任何功能，但负责定义"什么才算合格的功能"。

核心结果

本 task 的核心产物是一份名为 pxfquery_algorithm_package_delivery_anchor_v20260625.yaml 的机器可读 YAML，此外附带一张 11 行 × 9 列的能力证据矩阵、一份降级规则、一份评审量规和一份受控分类词汇表。

11 项被定义的能力覆盖了 PxFquery 的完整查询链路：forward query（扰动→功能响应）、reverse query（功能目标→候选扰动）、biological context handling（生物学上下文路由）、exact evidence routing（精确匹配优先）、proxy evidence routing（稀疏数据代理路由）、not-found/no-hit routing（安全空结果）、resolver-mediated entry（自然语言/半结构化入口）、LLM-assisted parsing/summarization（LLM 辅助解析与摘要）、deterministic fallback（确定性降级回退）、transparent evidence metadata（透明结果元数据）和 standard resource compatibility（标准资源兼容性）。每项能力都标注了触发条件、必需证据类型、验收阈值、已知失败模式和缺失处理方式。

降级规则中最关键的一条是：runtime fallback（运行时主路径失败后的自动回退）是有效的运行策略，但它不能替代主路径能力的交付验收。如果一个 milestone 承诺了 resolver 或 LLM 行为，仅仅因为 resolver 找不到索引或 LLM 超时就退回到确定性查询，这个 milestone 不能声称 resolver/LLM 能力已交付。类似的，manuscript claim restraint（手稿中对外声明的收敛）不能成为内部开发范围削减的理由。

项目价值

这套锚点将直接改变后续每个算法包里程碑的工作方式。对于执行 AI，能力矩阵是一份不能绕过的要求清单——不能只交付确定性查询就说完成。对于检查 AI，降级规则和量规提供了明确的分类标准——可以判断一个能力是 delivered、partial、blocked、failed、downgraded 还是 evidence-insufficient。对于人类验收者，分类词汇表确保状态标签的含义一致，不会出现同一个"partial"在不同任务中有不同解读。

长远来看，T-062 把项目从一个"边做边决定什么算完成"的状态推进到"锚点已固定，后续只需对照执行和检查"的状态。它节省的不是当前开发时间，而是未来每个里程碑验收时的争论时间。

后续使用方式

后续每个算法包里程碑任务（如 M1 内核、M2 解析器、M3 集成）应在执行前读取锚点 YAML，确定当前 milestone 覆盖哪些能力，然后逐项配置 required_when。里程碑完成时，评审应逐项对照能力矩阵，为每项在范围内的能力分配一个分类标签，记录使用了哪种证据、是否有 fallback 被触发、是否有降级或延期，以及延期是否获得用户批准。

如果里程碑只完成了 forward/reverse 确定性查询内核但遗漏了 resolver、LLM、proxy、not-found、metadata 或标准资源兼容性，那么即使内核跑得再快，里程碑也应被分类为 partial、blocked 或 downgraded，而不能自称 delivered。唯一的例外是 milestone 合同从开始就明确排除了这些能力，且这种排除不与项目能力锚点冲突。

边界与风险

T-062 的产物是治理锚点而非运行时证据。它不证明当前代码已满足任何一项能力的要求，不证明标准资源已能正常加载，不证明 resolver 可以正确分发查询，也不证明 LLM 路径可以正常工作。这些都需要后续执行 task 提供当前周期的跑通证据。锚点本身的能力定义和阈值也可能在项目认知更新时（例如实验性功能被验证或新的数据模式被采用）需要修订。修订时应遵循同样的降级规则：任何削弱都必须获得用户显式批准。
