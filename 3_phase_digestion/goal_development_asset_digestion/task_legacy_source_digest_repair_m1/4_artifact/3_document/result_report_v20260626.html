一句话结论：T-061 针对已注册的遗留 PxFquery 包源码目录完成了有界的静态审查，产出了一份干净的源摘要、一份模块复用矩阵和一份下游引用边界 YAML，为 M1/M1.1 开发任务提供了可信的遗留代码复用指南，取代了此前不可信的 T-041 输出。

1. 项目背景

PxFquery 是一个基于 LINCS 扰动-功能数据的生物信息学工作流，支持正向查询（扰动到功能响应）和反向查询（功能目标到候选扰动）。项目处于从历史 Windows 时代目录树向受控 macOS 工作空间迁移的阶段。M1 里程碑的目标是构建一个纯净的 Python 包，能够加载 h5ad 矩阵并执行确定性的正向/反向查询。然而，项目团队此前不清楚已迁移的遗留包源码中哪些部分可以直接复用、哪些需要改造、哪些已经过时。T-041 曾尝试回答这个问题，但其分析结果因方法论和权威性问题被标记为不可信。T-061 正是在这个缺口上启动的。

2. 核心结果

T-061 审查了 22 个 Python 源文件（共 25 个文件），覆盖约 3000 行遗留代码。核心发现如下：六个模块被判定为可直接复用——query/forward.py（255 行）和 query/reverse.py（276 行）包含 M1 所需的正向/反向查询引擎；utils.py（107 行）提供模糊匹配和余弦相似度等确定性辅助函数；logging_utils.py（77 行）提供日志配置工具；viz/plots.py（300 行）提供绘图辅助。四个索引类（细胞系、药物、功能、基因）被判定为可复用，但需要下游任务提前注册 JSON 索引文件。三个大型模块被判定为可适配但有风险——core.py（477 行）是现代外观层但其默认路径依赖需要显式覆盖；query/resolver.py（1072 行）提供了完整的证据感知查询解析能力但耦合了 LLM 客户端，建议推迟至 M1.1；llm/client.py（337 行）和 llm/prompts.py（386 行）提供可选的 LLM 支持但依赖外部 API。两个文件被标记为禁止用于 M1 运行时：main.py（125 行）是仅含方法桩的历史草稿，prompt/check_link.py（83 行）是临时的 API 连通性测试脚本。

3. 项目价值

这份消化的直接价值是消除了 M1 开发启动前的决策盲区。此前团队面对约 3000 行遗留代码时，不清楚哪些可以安全引入 M1 包、哪些需要隔离、哪些潜在陷阱（硬编码路径、API 凭据依赖、不完整的索引构建器）会在集成时触发问题。T-061 通过逐模块分类给出了明确的行动指令：M1 应聚焦于 query/forward.py、query/reverse.py 和 utils.py 作为确定性核心，避免对解析器和 LLM 层的早期依赖。这降低了 M1 的集成风险，将解析器等复杂组件的验证推迟到索引资产和模拟钩子就绪的 M1.1 阶段。同时，T-061 的输出也为项目阶段切换提供了具体的可审计证据——任何 M1 开发任务现在都可以引用 D-001 到 D-003 作为遗留代码解读的权威依据，不再依赖不可信的 T-041。

5. 后续使用方式

M1 开发任务应首先阅读 D-001 核心摘要，了解每个模块的复用分类和条件。然后使用 D-002 矩阵快速筛选出可直接复用的文件，并注意避开被禁止的 main.py 和 prompt/check_link.py。在将任何遗留模块引入 M1 包之前，应参照 D-003 中的条件清单，确保索引目录、矩阵路径和模拟配置已注册就绪。对于 query/resolver.py 和 LLM 层的引入，应在 M1.1 阶段进行——届时需先注册 JSON 索引、验证证据级别分类、并确保强制回退结果不会被误当作强生物学证据。T-061 的发现是静态审查结论，不能替代集成测试或生物验证。

6. 边界与风险

本任务未执行任何遗留包代码，未加载 h5ad 矩阵验证查询引擎的行为正确性，未确认 JSON 索引文件是否实际存在于预期路径，未检查 LLM 客户端在无网络环境下的降级行为。这意味着 D-001 中关于模块"可复用"的判定是结构层面的——代码在语法和逻辑结构上看起来可用，但未经运行时验证。下游任务必须为每个复用的模块编写确定性测试（例如使用小型 fixture 矩阵验证 ForwardQuery.query() 的返回结构），才能将模块视为已集成。此外，pyproject.toml 中的包发现配置可能需要调整，因为源码目录是包根目录而非嵌套的 pxfquery/ 子目录。建议 M1 实现任务在首次 pip install -e 前审查该配置。
