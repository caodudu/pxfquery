结果报告 — T-041 legacy_source_digest_for_m1

报告日期：2026-06-26

一、一句话结论

本任务对 PxFquery 遗留包源码完成了一次受控消化，确认了 10 个可安全引用的模块、4 个模块需谨慎处理、4 个文件禁止引用，并锁定了一项关键缺失资产（function_index.json），为 M1 的四个下游开发任务提供了清晰的引用边界。

二、项目背景

PxFquery 是一个基于 LINCS 数据的扰动-功能分析 Python 工具，当前项目阶段的目标是构建一个受控的 M1 Python 包里程碑。这个里程碑面临一个独特的挑战：项目中有一套经过手工迁移的遗留包源码，涉及数据加载、前向/反向查询、索引查找、解析器调度和 LLM 摘要等功能，但这些源码来自旧 Windows 项目结构，包含了硬编码路径、空实现桩模块和已不兼容的依赖配置。如果不做一次系统的源码消化，每个下游开发任务只能凭猜测使用这些遗留代码，由此产生的引用错误和路径假设会在开发过程中反复暴露。

三、核心结果

本次消化覆盖了遗留包的全部 15 个顶层条目和 20 余个源文件。可安全引用的模块包括 DataLoader（data/loader.py）、ForwardQuery（query/forward.py）和 ReverseQuery（query/reverse.py）的查询逻辑封装，四个索引类（CellLineIndex、DrugIndex、GeneIndex、FunctionIndex）的抽象和查找机制，以及工具函数模块（utils.py 中的 fuzzy_match、build_target_vector、cosine_similarity_matrix）和日志配置模块（logging_utils.py）。核心入口类 PxFquery（core.py）虽包含硬编码路径，但其 API 设计可作为 T046 的代码模板参考。

明确禁止使用的模块是 main.py（13 个方法全部为 pass）、prompt/check_link.py（功能被替代）、README.md（仅含旧路径）和 data/loader.py 中的 download_zenodo 方法（抛出 NotImplementedError）。Resolver 模块（query/resolver.py）被列为风险参考——它的 L1-L4 分层代理概念对 M2 有设计价值，但具体实现因耦合了旧路径和 LLM 不可直接复用。LLM 客户端和相关提示词模块在 M1 范围内不应作为核心功能引入。

本任务还定位了一项关键缺失：function_index.json 在迁移后的 data/query_indexes/ 中不存在，T052 必须在开发前使用遗留构建脚本重建此文件。

四、项目价值

对本项目的决策层而言，T-041 的价值不在于写了多少行代码，而在于消除了一项结构性风险：在 M1 四个开发任务并行推进前，提供了一份经过验证的「什么可以用、什么不能用、什么需要先修」的清单。如果没有这份消化，T046 可能会复制 main.py 的空框架，T048 可能误调用 download_zenodo 导致 NotImplementedError，T052 可能在缺少 function_index.json 的情况下调试索引类而浪费迭代轮次。此外，边界 YAML 为后续任务提供了自动可检查的约束规则，任何超出允许引用的使用都可以在 CI 或 Review 阶段被发现。

更长远地看，T-041 建立的「消化再开发」模式为项目中其他遗留资产（如 Old API Server、4t Notebooks、解析器脚本）的处理提供了可复用的流程模板：先通过 T-007 确认资产路径，再限定扫描范围、产出一份引用边界，然后才允许下游开发任务引用。

五、交付物导读

本任务共产生 7 项交付物，全部注册在 4_artifact/registry.yaml。作为后续任务的直接读者，你首先应该打开 4_artifact/2_persist/legacy_source_digest_m1.md，这份文档包含了每个模块的详细分析和逐文件推荐。如果想做快速评估，4_artifact/5_table/legacy_module_reuse_matrix_m1.csv 提供了可排序的表格视图。4_artifact/2_persist/legacy_reference_boundaries_m1.yaml 是机器可读的约束规则，建议 T046、T048、T049、T052 的开发者在设计阶段将其作为第一参考。两份 HTML 报告（执行报告和本报告）供项目负责人快速了解任务全貌，不需要重复阅读其他协议文件。

六、后续使用方式

T046（包脚手架）应在设计 pyproject.toml 和包入口 API 时参考 core.py 的类结构和依赖声明，但不应复制其内部路径常量。T048（数据加载与正向查询）可安全引用 data/loader.py 的 DataLoader API 和 query/forward.py 的 ForwardQuery/ForwardResult 类。T049（反向查询）可引用 query/reverse.py 的 ReverseQuery/ReverseResult 类，Resolver 的 L1-L4 概念可以用于设计讨论，但 Resolver 类的具体代码不可直接导入。T052（索引层）可以引用全部四个索引类的抽象和查找逻辑，但必须首先在开发环境中重建 function_index.json（使用遗留构建脚本 M-0373_build_function_index.py）。

所有下游任务必须使用 T-041 的输出作为引用依据，而不是直接读取遗留源码目录。这一约束记录在边界 YAML 中。

七、边界与风险

本任务只消化了 A-003 指向的一个遗留包目录。项目中可能还有其他有价值的遗留代码路径（例如旧解析器、旧可视化脚本），这些不在本次消化范围内，如需使用应创建新的消化任务。FunctionIndex 缺失资产的重建依赖一个遗留构建脚本，该脚本未经过本任务验证，T052 启动时可能遇到脚本兼容性问题。LLM 模块的引用被推迟到 M2 或更晚的里程碑，届时需要重新评估供应商选型和 API 设计。
