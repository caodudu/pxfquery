# 2. 介绍
Model Context Protocol

## 2.1 核心

MCP 是一个开放标准协议，用于让 AI 应用安全地连接到外部数据源和工具。

┌──────────────────────────────────────────────┐
│         AI 应用 (Claude/GPT/任何 LLM)         │
└──────────────────┬───────────────────────────┘
                   │ MCP 协议
        ┌──────────┴──────────┐
        │    MCP Server        │ ← 标准化接口
        └──────────┬──────────┘
                   │
    ┌──────────────┼──────────────┐
    │              │              │
 数据库          文件系统       第三方API
 (PostgreSQL)   (Google Drive)  (Slack)


MCP 确实就是一种标准化的胶水规范，把原本各自为政、重复劳动的"AI 调用工具"这件事，变成了一个统一的、可复用的标准。

🎯 核心：写一次 MCP Server，所有 AI 都能用；实现一次 MCP Client，所有工具都能调用。


┌─────────────────────────────────────────────────┐
│  第一方：AI Agent 生态（Claude、ChatGPT）         │
│  - 有自己的 API 调用规范                         │
│  - 有自己的工具调用方式                          │
└─────────────────────────────────────────────────┘
                      ↕
        【MCP = 中间翻译官/转换器】
                      ↕
┌─────────────────────────────────────────────────┐
│  第二方：软件生态（数据库、文件系统、API）         │
│  - 每个都有自己的访问方式                        │
│  - 每个都有自己的认证方式                        │
└─────────────────────────────────────────────────┘

## 2.2 用处
MCP 的架构
python
你的代码（任何框架）
  ↓
MCP Client（标准协议客户端）
  ↓
MCP Server（标准协议服务端）← 一次开发，到处使用
  ↓
各种 API

优势：
工具开发者只需实现一次 MCP Server
任何支持 MCP 的应用都能使用
类似于"USB 接口"的标准化

## 2.3 痛点

维度	没有 MCP	有 MCP
AI 的能力	被动接收	主动获取
你的工作	手动搬运数据	只说需求
交互模式	复制-粘贴	自然对话
AI 知道什么	只知道你给的	能"看到"连接的资源



痛点 1：工具重复开发
```python
# 同一个数据库工具，需要为不同框架写多次

# LangChain 版本
from langchain.tools import Tool
langchain_db_tool = Tool(name="db", func=query_db, ...)

# AutoGen 版本
from autogen import UserProxyAgent
autogen_db_tool = {"name": "db", "function": query_db, ...}

# Semantic Kernel 版本
from semantic_kernel import sk_function
sk_db_tool = sk_function(name="db")(query_db)
```

痛点 2：安全性问题
```python
# LangChain 中，AI 直接调用工具函数
@tool
def delete_database():  # 危险！
    os.system("rm -rf /data/*")

# 如果 AI 误判，可能造成灾难
```


痛点 3：权限管理缺失
```python
# LangChain 没有内置的权限系统
# 无法控制：
# - 哪个 AI 可以访问哪些数据？
# - 如何审计 AI 的操作？
# - 如何限制访问频率？
```

## 2.4 胶水规范
之前的世界（没有统一胶水）：

AI Agent A ←→ 自己写的胶水代码 ←→ 数据库
AI Agent A ←→ 自己写的胶水代码 ←→ 文件系统  
AI Agent A ←→ 自己写的胶水代码 ←→ API

AI Agent B ←→ 又得写一遍胶水代码 ←→ 数据库
AI Agent B ←→ 又得写一遍胶水代码 ←→ 文件系统
AI Agent B ←→ 又得写一遍胶水代码 ←→ API

问题：
- 每个 AI 都要自己写胶水
- 每个工具都要适配不同 AI
- 重复劳动


有了 MCP（标准化胶水）：

AI Agent A ←┐
AI Agent B ←┼→ MCP 协议（统一胶水）←→ 数据库
AI Agent C ←┘                        ←→ 文件系统
                                    ←→ API

好处：
- 工具开发者：只需实现一次 MCP Server
- AI 开发者：只需实现一次 MCP Client
- 用户：任何 AI 都能用任何工具


## 2.5 支持类型
1️⃣ 本地资源和工具
本地文件系统：读取、编辑你电脑上的文件
本地数据库：访问SQLite、PostgreSQL等本地数据库
本地应用：调用本地安装的软件和工具

2️⃣ 在线资源和远程服务
远程API：调用各种在线服务的API
云端数据库：连接远程数据库
在线工具：搜索引擎、计算器等网络服务



两种部署模式：
本地部署：

MCP服务器运行在你的电脑上，通过本地通信连接
适合处理敏感数据、本地文件等场景
更安全，不需要数据离开本地环境
远程部署：

MCP服务器运行在云端或远程服务器上
适合需要强大计算能力或访问云端资源的场景
可以多个客户端共享同一个MCP服务器


# 3. 组成 
## 3.1 MCP总构成：协议 + SDK + 服务器程序
MCP 不是一个软件，是三样东西：
 
MCP 包含：
├── 1. 一份协议规范文档（就像 HTTP 协议的 RFC 文档）
├── 2. 一些 SDK 代码库（帮你实现这个协议）
└── 3. 一些示例程序（MCP Server 的具体实现）
 
### 3.1.1 协议规范（一份文档）
就像 HTTP 规定了：

```vbnet
GET /index.html HTTP/1.1
Host: example.com
```

MCP 规定了：

```json
// AI 请求读取文件
{
  "jsonrpc": "2.0",
  "method": "tools/call",
  "params": {
    "name": "read_file",
    "arguments": {
      "path": "/path/to/file.txt"
    }
  }
}

// MCP Server 返回结果
{
  "jsonrpc": "2.0",
  "result": {
    "content": "文件内容..."
  }
}
```

你可以在这里看到完整规范：https://spec.modelcontextprotocol.io/


### 3.1.2 SDK（代码库）
帮你实现这个协议的库，避免手写通信代码。

```bash
# Python SDK
pip install mcp

# TypeScript SDK
npm install @modelcontextprotocol/sdk
就像使用 HTTP 库：

python
# 你不会手写 TCP 套接字来发 HTTP 请求
# 而是用库
import requests
requests.get("https://example.com")

# 同理，你不会手写 JSON-RPC
# 而是用 MCP SDK
from mcp.server import Server
app = Server("my-server")
```


### 3.1.3 MCP Server（具体程序）
这是真正干活的程序，每个 Server 负责一类资源。

官方提供的 Server（现成的小程序）：

Server 名称	功能	安装命令
mcp-server-filesystem	访问本地文件	npm install -g @modelcontextprotocol/server-filesystem
mcp-server-postgres	访问 PostgreSQL	npm install -g @modelcontextprotocol/server-postgres
mcp-server-github	访问 GitHub API	npm install -g @modelcontextprotocol/server-github
mcp-server-google-drive	访问 Google Drive	npm install -g @modelcontextprotocol/server-google-drive


这些都是独立运行的小程序，就像：

```bash
# 启动一个 Web 服务器
$ python -m http.server 8000

# 启动一个 MCP 服务器
$ mcp-server-filesystem --allowed-directory ./data
```

## 3.2 架构组成
https://arxiv.org/pdf/2503.23278
MCP架构由三个核心组件组成:MCP主机、MCP客户端和MCP服务器。
这些组件协同工作,促进AI应用程序、外部工具和数据源之间的无缝通信,确保操作的安全性和正确管理。

在典型的工作流程中,
用户向MCP客户端发送提示,客户端分析意图,通过MCP服务器选择适当的工具,
并调用外部API来检索和处理所需信息,然后将结果通知用户。

### **3.2.1 MCP主机**  MCP Host
- MCP主机是一个AI应用程序,在运行MCP客户端的同时提供执行基于AI任务的环境
- 集成交互式工具和数据,实现与外部服务的顺畅通信
- 示例包括:
  - Claude Desktop:用于AI辅助内容创作
  - Cursor:用于代码补全和软件开发的AI驱动IDE
  - AI智能体:作为执行复杂任务的自主系统
- **托管MCP客户端,并确保与外部MCP服务器的通信**

### **3.2.2 MCP客户端**  MCP Client (框架自带)
- 在MCP主机-客户端-服务器架构中充当主机环境内的中介组件
- 与其对应的MCP服务器维护一对一的通信链路
- 主要功能:
  - **代表主机运行,向MCP服务器发起请求**
  - **查询可用函数**
  - 检索描述服务器工具、资源和能力的响应
  - 处理来自MCP服务器的通知,提供任务进度和系统状态的实时更新
  - 执行采样以收集工具使用和性能数据,实现优化和决策制定
- 通过传输层与MCP服务器通信,促进安全、可靠的数据交换
- 使主机能够无缝访问和利用MCP服务器提供的外部功能

### **3.2.3 MCP服务器**  MCP Server (下载部署的)

```
连接层（网络/数据访问）+ 业务工具/函数层（暴露给AI的能力）
```



MCP服务器使MCP主机和客户端能够访问外部系统并执行操作,提供三个核心能力:

**• 工具:启用外部操作**
- 使服务器能够调用外部服务和API来代表AI模型执行操作
- 工作流程:
  1. 主机应用程序通过客户端查询MCP服务器,获取可用工具及其能力的列表
  2. 主机根据任务上下文选择适当的工具,通过客户端发出调用请求
  3. MCP服务器通过外部服务或API执行相应操作
  4. 将结果返回给客户端,客户端再转发给主机
- 特点:
  - 通过标准化的、与模型无关的协议进行描述和访问
  - 允许工具在异构AI系统中被动态发现、描述和调用
  - 确保跨平台互操作性而非特定提供商的集成
  - 支持主机和服务的双向通信,实现异步更新或事件流等丰富交互
  - 遵循供应-消费模型,促进模块化和可重用性
  - 允许独立开发的工具无缝互操作,提高系统效率和可扩展性

**• 资源:向AI模型暴露数据**
- 提供对结构化和非结构化数据集的访问
- 数据来源:本地存储、数据库或云平台
- 工作方式:当AI模型请求特定数据时,MCP服务器检索并处理相关信息
- 使模型能够做出数据驱动的决策
- 应用示例:
  - 推荐系统访问客户交互日志
  - 文档摘要任务查询文本存储库

**• 提示:用于工作流程优化的可重用模板**
- 预定义模板和工作流程,由MCP服务器生成和维护
- 作用:
  - 优化AI响应
  - 简化重复性任务
  - 确保响应的一致性
  - 提高任务执行效率
- 应用示例:
  - 客户支持聊天机器人使用提示模板提供统一且准确的响应
  - 标注任务依赖预定义提示保持数据标注的一致性

## 4.3 通信对比

场景：让 Claude 读取你电脑上的文件
没有 MCP 之前（传统方式）
 
```markdown
你：Claude，总结 report.txt

Claude：我看不到你的文件，请把内容复制给我
         ↑
      【被动】只能等你喂数据

你：【手动操作】
    1. 找到文件
    2. 复制内容
    3. 粘贴到对话框
    4. 发送

Claude：好的，开始总结...（处理你粘贴的内容）
```

```python
# 你需要在你的应用里写代码
import anthropic

client = anthropic.Client()

# 1. 手动读取文件
with open("report.txt") as f:
    content = f.read()

# 2. 把文件内容粘贴到 prompt 里
response = client.messages.create(
    model="claude-3",
    messages=[{
        "role": "user", 
        "content": f"总结这个文件：\n{content}"  # 文件内容直接塞进去
    }]
)
```

问题：

每次都要手动读文件
文件太大会超出 token 限制
Claude 只能"被动接收"，不能"主动访问"



有 MCP 之后
```markdown
你：Claude，总结 report.txt

Claude：【主动行动】
    1. "我需要读取文件"
    2. "看看有没有文件读取工具...有！"
    3. 通过 MCP 协议发送请求：
       → MCP Server: 请帮我读取 report.txt
    4. ← MCP Server: 给你内容
    5. 总结内容
    6. 回复你

你：【什么都不用做】
```




步骤 1：启动一个 MCP Server（一个小程序）
```bash
# 这是一个独立运行的小程序
# 类似于启动一个 Web 服务器
$ npm install -g @modelcontextprotocol/server-filesystem
$ mcp-server-filesystem --allowed-directory /Users/you/Documents
```

这个程序在干什么？

它在你电脑上运行
等待接收"读取文件"的请求
处理请求后返回文件内容


步骤 2：告诉 Claude Desktop 这个 Server 的存在
```json
// 编辑配置文件：~/.config/claude/config.json
{
  "mcpServers": {
    "filesystem": {
      "command": "mcp-server-filesystem",
      "args": ["--allowed-directory", "/Users/you/Documents"]
    }
  }
}
```

步骤 3：Claude 自动发现并使用
 
你：Claude，帮我总结 Documents 文件夹里的 report.txt

Claude 内部流程：
1. "哦，用户想访问文件"
2. "我看看有没有可用的工具...有一个 filesystem MCP Server"
3. 发送请求到 MCP Server："读取 /Users/you/Documents/report.txt"
4. MCP Server 返回文件内容
5. Claude 总结内容并回复你
关键：你不需要写任何代码！Claude 和 MCP Server 自动通信。

```python
# 你公司的客户管理系统没有现成的 MCP Server
# 你可以自己写一个

from mcp.server import Server
import mcp.types as types

app = Server("company-crm")

@app.list_tools()
async def list_tools():
    return [
        types.Tool(
            name="get_customer",
            description="获取客户信息",
            inputSchema={
                "type": "object",
                "properties": {
                    "customer_id": {"type": "string"}
                }
            }
        )
    ]

@app.call_tool()
async def call_tool(name: str, arguments: dict):
    if name == "get_customer":
        # 调用你公司的内部 API
        customer = company_api.get_customer(arguments["customer_id"])
        return [types.TextContent(
            type="text",
            text=str(customer)
        )]

# 启动服务器
```

# 6. 配合
## 6.1 fastapi
**MCP vs FastAPI 的区别：**
MCP的定位：
专门为AI模型设计的协议，让AI能够调用工具和访问数据
主要用于AI与工具之间的通信
客户端通常是AI应用（如Claude Desktop、LangChain agents等）
强调的是AI上下文传递和工具调用
FastAPI的定位：
通用的Web API框架，用于构建RESTful服务
主要用于人类用户、前端应用、各种系统之间的HTTP通信
客户端可以是浏览器、手机App、其他后端服务等
强调的是标准化的Web服务接口

**实际应用场景对比：**
需要FastAPI的情况：
构建面向用户的Web应用后端
提供RESTful API给前端调用
需要复杂的认证、授权、限流等Web服务功能
服务需要被非AI客户端访问
需要标准的HTTP协议和OpenAPI文档
使用MCP的情况：
让AI模型访问你的数据和工具
为AI agent提供扩展能力
构建AI专用的工具集成
需要AI理解的上下文和资源管理


**两者可以共存：**
实际项目中，它们经常一起使用：

用户浏览器 → FastAPI → 业务逻辑 → MCP → AI模型 → MCP工具


举例：
用FastAPI构建一个聊天应用的后端API
用户通过FastAPI发送消息
后端调用Claude，Claude通过MCP访问本地文件或数据库
FastAPI再把结果返回给用户
