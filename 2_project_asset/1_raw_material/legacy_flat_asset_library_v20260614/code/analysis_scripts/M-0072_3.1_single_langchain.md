# 2. 介绍
## 2.1 核心介绍
LangChain是一个开源的AI应用开发框架，通过标准化的接口和组件化设计，让开发者能够快速构建基于大语言模型的复杂应用，包括聊天机器人、文档问答系统、AI Agent等。


## 2.2 用处
框架主要解决了LLM应用开发中的关键挑战：Prompt管理、外部数据集成、对话记忆、工具调用、多步推理等。2025年版本重点加强了多智能体协作（LangGraph）、表达式语言（LCEL）、人机交互循环等能力，形成了从原型到生产的完整开发链路。

## 2.3 为什么需要langchain

总结：复杂性的递进
阶段	需求	            OpenAI SDK	                需要 LangChain？
0	单次问答	            ✅ 简单	                    ❌ 不需要
1	结构化输出	            ✅ 原生支持	                ❌ 不需要
2	单次工具调用	        ⚠️ 需要胶水代码	              🤔 可选
3	多次工具调用（ReAct）	❌ 需要大量代码	            ✅ 强烈推荐
4	记忆管理	            ❌ 需要手动实现	            ✅ 强烈推荐
5	文档 RAG	            ❌ 需要完整流程	            ✅ 必需
6	多 Agent 协作	        ❌ 极其复杂	                ✅ 必需


OpenAI SDK 是"原子能力"
提供基础的模型调用
提供 Function Calling 能力
但不管理"流程"和"状态"
LangChain 是"流程编排"
封装常见模式（ReAct、RAG）
管理状态和记忆
提供工具生态
类比
OpenAI SDK  ≈  HTTP 库（如 requests）
LangChain   ≈  Web 框架（如 Django/FastAPI）

你可以用 requests 手写整个 Web 服务，
但用 Django 会省下 90% 的代码。



### 2.3.1 多次工具调用（ReAct 模式）
需求：让 AI 连续使用多个工具
场景：「帮我查北京天气，如果下雨就订一辆车」

```python
messages = [{"role": "user", "content": "帮我查北京天气，如果下雨就订车"}]

# 需要循环多次
max_iterations = 10
for i in range(max_iterations):
    response = client.chat.completions.create(
        model="gpt-4",
        messages=messages,
        tools=tools
    )
    
    assistant_message = response.choices[0].message
    messages.append(assistant_message)
    
    # 检查是否有工具调用
    if assistant_message.tool_calls:
        for tool_call in assistant_message.tool_calls:
            # 根据工具名称调用不同函数
            if tool_call.function.name == "get_weather":
                result = get_weather(...)
            elif tool_call.function.name == "book_car":
                result = book_car(...)
            # ... 更多工具
            
            # 添加工具结果到消息
            messages.append({
                "role": "tool",
                "tool_call_id": tool_call.id,
                "content": result
            })
    else:
        # AI 完成了任务
        break

final_answer = messages[-1].content
```

出现的问题：

❌ 需要手动实现 ReAct 循环
❌ 需要自己管理消息历史（messages 数组）
❌ 需要手动映射工具名称到函数
❌ 需要设置最大迭代次数防止死循环
❌ 需要处理错误（如果工具调用失败怎么办？）
复杂度：😫 相当复杂，代码重复多
结论：这就是 LangChain 开始有价值的地方！



用 LangChain 重写上面的场景
```python
from langchain_openai import ChatOpenAI
from langchain.agents import create_openai_functions_agent, AgentExecutor
from langchain.tools import tool

# 1. 定义工具（自动注册）
@tool
def get_weather(location: str) -> str:
    """获取天气信息"""
    return f"{location}的天气是晴天"

@tool
def book_car() -> str:
    """预订车辆"""
    return "已成功预订车辆"

# 2. 创建 Agent（自动处理循环）
llm = ChatOpenAI(model="gpt-4")
tools = [get_weather, book_car]
agent = create_openai_functions_agent(llm, tools, prompt)
executor = AgentExecutor(agent=agent, tools=tools, verbose=True)

# 3. 一行代码执行
result = executor.invoke({"input": "帮我查北京天气，如果下雨就订车"})
```
LangChain 帮你做了什么：

✅ 自动实现 ReAct 循环
✅ 自动管理消息历史
✅ 自动映射工具名称到函数
✅ 自动处理工具调用的序列化/反序列化
✅ 内置错误处理和重试机制
✅ 提供日志和调试（verbose=True）

for chunk in chunks:
    emb = client.embeddings.create(input=chunk, model="text-embedding-3-small")

# 4. 用户提问时，手动检索

# 5. 手动构造 prompt

用 LangChain：

```python
from langchain.document_loaders import TextLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings
from langchain.vectorstores import Chroma
from langchain.chains import RetrievalQA

# 1. 加载文档（自动）
loader = TextLoader("doc.txt")
documents = loader.load()

# 2. 切分（自动）
splitter = RecursiveCharacterTextSplitter(chunk_size=1000)
chunks = splitter.split_documents(documents)

# 3. 向量化和存储（自动）
embeddings = OpenAIEmbeddings()
vectorstore = Chroma.from_documents(chunks, embeddings)

# 4. 创建检索链（自动）
qa = RetrievalQA.from_chain_type(
    llm=ChatOpenAI(),
    retriever=vectorstore.as_retriever()
)

# 5. 一行代码查询
result = qa.invoke({"query": "文档里说了什么？"})
```
节省的工作量巨大！

### 3.3.2 短期记忆 - 滑动窗口 ConversationBufferWindowMemory
原理：只保留最近 N 轮对话
手动实现（OpenAI SDK）：

```python
class ConversationMemory:
    def __init__(self, max_turns=5):
        self.messages = []
        self.max_turns = max_turns
    
    def add_message(self, role, content):
        self.messages.append({"role": role, "content": content})
        
        # 只保留最近 N 轮（每轮 = user + assistant）
        if len(self.messages) > self.max_turns * 2:
            # 保留系统消息 + 最近 N 轮
            self.messages = self.messages[:1] + self.messages[-(self.max_turns * 2):]
    
    def get_messages(self):
        return self.messages

# 使用
memory = ConversationMemory(max_turns=3)
memory.add_message("user", "我叫张三")
memory.add_message("assistant", "你好张三")
# ... 更多对话 ...
memory.add_message("user", "我叫什么？")

response = client.chat.completions.create(
    model="gpt-4",
    messages=memory.get_messages()  # 只包含最近 3 轮
)
```

### 3.3.3 压缩记忆 - AI 自动总结 ConversationSummaryMemory
原理：用 AI 总结历史对话，保留摘要而非原文
流程：

```markdown
第 1-5 轮对话（原文）
    ↓
用 AI 总结成 1 段话
    ↓
第 6-10 轮对话（原文）
    ↓
用 AI 再次总结（包含之前的摘要）
    ↓
总摘要 + 最近 2 轮原文
```

手动实现：
```python
def summarize_conversation(messages):
    """用 AI 总结对话历史"""
    conversation_text = "\n".join([
        f"{msg['role']}: {msg['content']}" 
        for msg in messages
    ])
    
    summary_response = client.chat.completions.create(
        model="gpt-4",
        messages=[{
            "role": "user",
            "content": f"请总结以下对话的关键信息：\n{conversation_text}"
        }]
    )
    
    return summary_response.choices[0].message.content

# 使用
full_history = []  # 完整历史
summary = ""       # 当前摘要

def chat(user_input):
    global summary, full_history
    
    # 添加新消息
    full_history.append({"role": "user", "content": user_input})
    
    # 如果历史太长（例如超过 10 条），进行总结
    if len(full_history) > 10:
        summary = summarize_conversation(full_history[:-2])  # 总结除了最近 2 条
        full_history = full_history[-2:]  # 只保留最近 2 条原文
    
    # 构造 prompt
    messages = []
    if summary:
        messages.append({"role": "system", "content": f"对话摘要：{summary}"})
    messages.extend(full_history)
    
    # 调用 AI
    response = client.chat.completions.create(model="gpt-4", messages=messages)
    assistant_reply = response.choices[0].message.content
    
    full_history.append({"role": "assistant", "content": assistant_reply})
    return assistant_reply
```

用 LangChain：

```python
from langchain.memory import ConversationSummaryMemory

# 自动总结历史
memory = ConversationSummaryMemory(
    llm=ChatOpenAI(),
    max_token_limit=1000  # 超过 1000 tokens 就总结
)

conversation = ConversationChain(
    llm=ChatOpenAI(),
    memory=memory
)

conversation.predict(input="我叫张三")
conversation.predict(input="我在北京工作")
# ... 100 轮对话后 ...
conversation.predict(input="我的基本信息是？")  # ✅ 能记住（通过摘要）

# 查看摘要
print(memory.buffer)  # 输出：用户叫张三，在北京工作...
```

优点：
✅ 能记住较长历史
✅ token 使用优化（摘要比原文短）

缺点：
❌ 需要额外 API 调用（总结需要消耗 token）
❌ 可能丢失细节信息
❌ 总结质量依赖模型能力


### 3.3.4 长期记忆 - 向量数据库存储 VectorStoreRetrieverMemory
原理：把所有对话存入向量数据库，需要时检索相关内容
架构：

```markdown
用户提问
    ↓
1. 把问题转换为向量（embedding）
    ↓
2. 在向量数据库中搜索相似的历史对话
    ↓
3. 检索出最相关的 3-5 条历史
    ↓
4. 把检索结果 + 当前问题一起发给 AI
```


手动实现：
```python
import numpy as np
from sklearn.metrics.pairwise import cosine_similarity

class VectorMemory:
    def __init__(self):
        self.memories = []  # 存储 {"text": "...", "embedding": [...]}
    
    def add_memory(self, text):
        """添加记忆"""
        # 1. 生成 embedding
        embedding_response = client.embeddings.create(
            model="text-embedding-3-small",
            input=text
        )
        embedding = embedding_response.data[0].embedding
        
        # 2. 存储
        self.memories.append({
            "text": text,
            "embedding": embedding
        })
    
    def search(self, query, k=3):
        """检索相关记忆"""
        # 1. 把查询转换为向量
        query_embedding = client.embeddings.create(
            model="text-embedding-3-small",
            input=query
        ).data[0].embedding
        
        # 2. 计算相似度
        similarities = []
        for memory in self.memories:
            sim = cosine_similarity(
                [query_embedding], 
                [memory["embedding"]]
            )[0][0]
            similarities.append((memory["text"], sim))
        
        # 3. 返回最相关的 k 条
        similarities.sort(key=lambda x: x[1], reverse=True)
        return [text for text, _ in similarities[:k]]

# 使用
memory = VectorMemory()

# 添加历史对话
memory.add_memory("用户说他叫张三")
memory.add_memory("用户说他在北京工作")
memory.add_memory("用户喜欢吃披萨")
# ... 1000 条对话 ...

# 用户提问
query = "我的名字是什么？"
relevant_memories = memory.search(query, k=3)
# 返回：["用户说他叫张三", ...]

# 构造 prompt
context = "\n".join(relevant_memories)
messages = [
    {"role": "system", "content": f"相关历史信息：\n{context}"},
    {"role": "user", "content": query}
]

response = client.chat.completions.create(model="gpt-4", messages=messages)
```


用 LangChain：
```python
from langchain.memory import VectorStoreRetrieverMemory
from langchain_openai import OpenAIEmbeddings
from langchain.vectorstores import Chroma

# 1. 创建向量数据库
embeddings = OpenAIEmbeddings()
vectorstore = Chroma(
    collection_name="chat_history",
    embedding_function=embeddings
)

# 2. 创建记忆
memory = VectorStoreRetrieverMemory(
    retriever=vectorstore.as_retriever(search_kwargs={"k": 3})
)

# 3. 使用
conversation = ConversationChain(
    llm=ChatOpenAI(),
    memory=memory
)

conversation.predict(input="我叫张三")
conversation.predict(input="我在北京工作")
# ... 1000 轮对话后 ...
conversation.predict(input="我叫什么名字？")  # ✅ 能检索到相关记忆
```

优点：

✅ 可以存储海量历史（数万条）
✅ 语义搜索，能找到相关但不是原话的信息
✅ 适合长期对话
缺点：

❌ 需要向量数据库（额外基础设施）
❌ 检索可能不准确（依赖 embedding 质量）
❌ 增加延迟（需要检索时间）


### 3.3.5 混合策略（实际生产常用） CombinedMemory
最佳实践：三层记忆架构
```python
from langchain.memory import CombinedMemory, ConversationBufferWindowMemory, \
                              ConversationSummaryMemory, VectorStoreRetrieverMemory

# 1. 短期记忆：最近 3 轮对话（原文）
short_term = ConversationBufferWindowMemory(
    k=3,
    memory_key="short_term"
)

# 2. 中期记忆：总结
mid_term = ConversationSummaryMemory(
    llm=ChatOpenAI(),
    memory_key="summary"
)

# 3. 长期记忆：向量检索
long_term = VectorStoreRetrieverMemory(
    retriever=vectorstore.as_retriever(),
    memory_key="long_term"
)

# 组合记忆
memory = CombinedMemory(memories=[short_term, mid_term, long_term])

conversation = ConversationChain(
    llm=ChatOpenAI(),
    memory=memory
)
```

用户："我叫什么名字？"

### 3.3.6 关系型记忆
工作原理：

AI 自动识别对话中的"实体"（人名、地点、物品等）
为每个实体维护一个描述
后续对话中，如果提到该实体，会自动加载相关信息

问题	答案
LangChain 支持索引化笔记吗？	✅ 支持（Entity Memory）
能自定义存储结构吗？	✅ 可以（继承 BaseChatMemory）
能连接关系数据库吗？	✅ 可以（自定义后端）
向量化和索引化能共存吗？	✅ 推荐混合使用


```python
from langchain.memory import ConversationEntityMemory
from langchain_openai import ChatOpenAI
from langchain.chains import ConversationChain

# 创建实体记忆（自动提取和索引关键信息）
memory = ConversationEntityMemory(
    llm=ChatOpenAI(),
    entity_store={}  # 可以用字典或数据库
)

conversation = ConversationChain(
    llm=ChatOpenAI(),
    memory=memory,
    verbose=True
)

# 对话
conversation.predict(input="我叫张三")
conversation.predict(input="我在北京工作")
conversation.predict(input="我喜欢吃披萨")

# 查看实体存储（结构化索引）
print(memory.entity_store)
```

messages = prompt.format_messages(role="teacher", input="Explain Python")

## 3.5 MCP工具调用

### 3.5.2 自己设计MCP

创建 weather_server.py：
```Python
from mcp import Server, Tool, run
import httpx
from typing import Dict, Any

async def get_forecast(city: str) -> Dict[str, Any]:
    """获取城市天气预报"""
    async with httpx.AsyncClient() as client:
        resp = await client.get(f"https://api.weatherapi.com/v1/forecast.json?key=YOUR_KEY&q={city}")
        return resp.json()

server = Server(
    name="my-weather-mcp",
    version="1.0.0",
    description="Simple weather MCP server",
)

server.add_tool(
    Tool(
        name="get_forecast",
        description="Get weather forecast for a city",
        parameters={
            "type": "object",
            "properties": {"city": {"type": "string", "description": "City name"}},
            "required": ["city"],
        },
        func=get_forecast,
    )
)

if __name__ == "__main__":
    run(server, transport="http")  # 或 "stdio"
```

完整示例代码（多服务器 + ReAct Agent）
```Python
# 文件: langchain_mcp_example.py
# 日期: 2026-01 更新版

import asyncio
from langchain_mcp_adapters.client import MultiServerMCPClient
from langchain_mcp_adapters.tools import load_mcp_tools  # 可选，client.get_tools() 也行
from langgraph.prebuilt import create_react_agent
from langchain_openai import ChatOpenAI
# from langchain_anthropic import ChatAnthropic  # 备选模型

# ==================== 配置 MCP 服务器 ====================
mcp_config = {
    "weather": {  # 社区或自己跑的天气MCP
        "transport": "http",
        "url": "http://localhost:8000/mcp",  # 替换成实际URL
        # "headers": {"Authorization": "Bearer YOUR_TOKEN"},
    },
    "github": {  # 示例：Composio 或社区GitHub MCP
        "transport": "http",
        "url": "https://github-mcp.example.com/mcp",  # 从registry复制
    },
    "filesystem": {  # 本地stdio示例（推荐开发测试）
        "transport": "stdio",
        "command": "python",
        "args": ["/path/to/server-filesystem.py", "/tmp/myfolder"],  # 绝对路径！
    },
}

# ==================== 主程序 ====================
async def main():
    # 创建客户端（支持多服务器）
    client = MultiServerMCPClient(mcp_config)

    # 方式1：加载所有工具（推荐）
    tools = await client.get_tools()  # 自动发现并转换为LangChain Tool

    # 方式2：带session管理（有状态工具推荐）
    # async with client.session() as session:
    #     tools = await load_mcp_tools(session)

    # 初始化LLM（可换成Claude、Groq、DeepSeek等）
    llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
    # llm = ChatAnthropic(model="claude-3-5-sonnet-20241022")

    # 创建ReAct Agent（最简单agent）
    agent = create_react_agent(llm, tools)

    # 执行查询（支持stream）
    query = "上海明天天气如何？然后在我的本地 /tmp/test.txt 里写一句'Hello MCP'"
    response = await agent.ainvoke({"messages": query})

    print("最终回答：")
    print(response["messages"][-1].content)

    # 清理（可选，但stdio服务器建议）
    await client.aclose()

if __name__ == "__main__":
    asyncio.run(main())
```


变体 & 常见修改点：

加认证：在dict里加 "headers": {"Authorization": "Bearer xxx"}
只用单个服务器：把mcp_config改成单个dict
用LangGraph自定义图：替换 create_react_agent 为自己的StateGraph
Stream输出：agent.astream_events(...)
错误处理：加try-except + client的on_connection_error="log"参数
